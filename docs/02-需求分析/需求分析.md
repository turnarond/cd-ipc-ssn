## 1. 框架定位与目标

### 1.1 框架定位

SSN（Scalable Socket Network，可扩展套接字网络）是一个轻量级 IPC/分布式通信框架（面向 v2.4.1）：

- 基于 C99 实现，支持 RPC、发布/订阅（PubSub）、点对点消息三种通信模式；
- 运行于 Unix Domain Socket / TCP / UDP 之上，统一传输接口与工厂；
- 分层架构：节点抽象层 → 客户端/服务端层 → 协议层 → 传输层 → VSI 平台抽象层（见白皮书第 2 章）；
- 采用类似 DDS 的分布式节点模型（`ssn_node_t` 双角色），淡化传统客户端/服务端模式；
- 定位声明：对 DDS 采用「概念借鉴型」定位（见第 4 章），保持轻量 IPC 定位，不追求 OMG 规范
  全量实现、RTPS 线协议互操作或与 FastDDS/OpenDDS 等真实 DDS 实现兼容。

### 1.2 目标场景

1. **边缘计算**：边缘节点间的轻量数据分发，支撑设备采集数据的实时上报与指令下发；
2. **进程间通信**：单机多进程间的高性能通信（Unix Socket 场景），替代裸 socket 编程；
3. **设备互联**：跨设备、跨网络的分布式通信（TCP/UDP 场景），实现多设备互联互通；
4. **演进愿景**：对标 DDS 逐步演进为「以数据为中心的分布式通信框架」（见第 4 章 DDS 对标
   需求映射）。

### 1.3 设计原则

1. **分层**：模块化设计，各组件职责清晰，便于扩展与维护；
2. **轻量**：C99 实现、无重量级外部依赖，保持轻量 IPC 定位；
3. **中文文档**：完整中文文档体系，按阅读顺序编号组织（`docs/` 目录）；
4. **向后兼容**：API、配置与协议兼容，提供迁移指南（`docs/04-实施规划/迁移指南.md`）；
5. **性能优先**：在保证功能完整性的前提下优化性能；
6. **TDD 流程**：先写测试后实现，测试在 WSL 中运行验证（见 `CLAUDE.md`）。

### 1.4 需求范围

- 本文档 FR/NFR 描述 v2.4.1 当前版本应具备的能力基线，DR 为后续版本的演进需求；
- **明确不在 v2.4.1 范围内**：TLS/DTLS 安全传输、连接池管理、数据压缩（LZ4/Zstd）、多级 QoS
  调度与流量整形等细化算法（愿景未实现，见白皮书第 10 章能力矩阵）。

## 2. 功能需求

### 2.1 需求总览

| 编号 | 需求名称 | 优先级 | 对应实现/依据 |
|------|---------|--------|--------------|
| FR-01 | 节点抽象 | P0 | `src/node/ssn_node.c`、`ssn_node.h` |
| FR-02 | RPC 请求/应答 | P0 | `src/protocol/rpc/` |
| FR-03 | 发布/订阅 | P0 | `src/protocol/pubsub/` |
| FR-04 | 点对点消息 | P0 | `src/protocol/msg/` |

| FR-07 | QoS 基础 | P1 | 设计预留（`SSN_NODE_CAP_QOS`），落地差距见第 4 章 |

| FR-09 | 版本管理与错误码体系 | P0 | `src/version/`、`src/ssn_error.c` |

### FR-01 节点抽象

- **描述**：提供 `ssn_node_t` 节点抽象，统一封装服务端与客户端双角色能力（默认能力位
  `SSN_NODE_CAP_RPC` / `SSN_NODE_CAP_PUBSUB` / `SSN_NODE_CAP_SERVER` /
  `SSN_NODE_CAP_CLIENT`，另预留 `SSN_NODE_CAP_DISCOVERY` / `SSN_NODE_CAP_QOS`）；
  支持节点生命周期管理（create 后进入 STOPPED、start 后进入 ACTIVE、stop 回到 STOPPED、
  出错进入 ERROR，代码为三态简化状态机）、唯一标识与自描述（node_id/node_type/node_name）、
  服务注册、主题订阅管理、RPC 方法注册、点对点消息收发与运行统计；节点可同时作为数据生产者、
  消费者或服务提供者。
- **优先级**：P0
- **验收要点**：`test_node_basic`（3 例）、`test_node`（6 例）通过；节点双角色通信往返可用；
  生命周期状态迁移符合代码三态定义（`SSN_NODE_STATE_STOPPED` / `SSN_NODE_STATE_ACTIVE` /
  `SSN_NODE_STATE_ERROR`，见 `src/node/ssn_node.h`；白皮书 3.3 为设计状态机，代码当前为三态
  简化实现，需求基线以代码现状为准）。

### FR-02 RPC 请求/应答

- **描述**：基于 `ssn_rpc` 模块，服务端注册方法（`ssn_node_add_rpc_method` 等）、客户端发起
  同步调用并接收应答；支持超时控制、错误码返回与回调应答两种方式。
- **优先级**：P0
- **验收要点**：`test_protocol`（25 例）与 `test_protocol_integration`（19 例）中 RPC 用例
  通过；超时场景返回 `SSN_ECODE_TIMEOUT`。

### FR-03 发布/订阅

- **描述**：基于 `ssn_pubsub` 模块，支持主题订阅、消息发布与分发、退订；发布端与订阅端仅通过
  主题名解耦，订阅端收到消息后经回调分发。
- **优先级**：P0
- **验收要点**：`test_protocol`/`test_protocol_integration` 中发布订阅用例通过；
  `examples/basic/03_pubsub` 可运行。

### FR-04 点对点消息

- **描述**：基于 `ssn_msg` 模块，支持点到点消息定向发送与接收（send/recv）；发送方需在消息中
  携带目标 URL（`ssn_url_ref_t`）。
- **优先级**：P0
- **验收要点**：`test_protocol` 消息用例通过；`examples/basic/01_hello_world` 消息往返可用。

### FR-05 多传输支持

- **描述**：统一传输接口 `ssn_transport_t` 与工厂 `ssn_transport_factory`，支持 Unix Domain
  Socket、TCP、UDP 三种传输实现（传输类型枚举含 TCP6/UDP6）；统一地址格式：`tcp://host:port`、
  `unix:///path`、`udp://host:port`；支持 bind/listen/accept/connect/send/recv 基本操作与
  连接统计。
- **优先级**：P0
- **验收要点**：`test_transport`（55 例）通过；`examples/protocols/01_unix_socket`、`02_tcp`、
  `03_udp` 构建并可运行；UDP 无连接特性符合限制标注（见部署手册 4.3）。

### FR-06 节点发现

- **描述**：提供节点自动发现与注册能力，支持组播/广播/目录服务等发现模式；发现消息包含宣告
  （ANNOUNCE）、查询（QUERY）、响应（RESPONSE）、心跳（HEARTBEAT）、离开（GOODBYE）；支持心跳
  超时故障检测、重试与状态同步。当前代码仅预留能力位（`SSN_NODE_CAP_DISCOVERY`），完整实现待
  后续版本（与 DDS 演进阶段 3 的发现增强衔接，见 DR-05）。
- **优先级**：P1
- **验收要点**：以 `docs/03-设计/核心模块/节点发现设计.md` 为设计参考（注：该文档当前标注
  「部分过时」，实现时需重新校准）；DDS 阶段 3 落地时以 `test/test_dds_discovery.c` 验证。

### FR-07 QoS 基础

- **描述**：提供服务质量基础框架：可靠性（尽力而为 / 至少一次 / 至多一次 / 精确一次 / 可靠）、
  优先级、带宽的配置模型（`ssn_qos_config_t`，含重试次数、截止时间、最大带宽、延迟/抖动上限、
  TTL 等字段）；多级调度队列、流量整形、延迟保障等细化算法为愿景方向，不在当前版本范围。当前
  代码仅预留能力位（`SSN_NODE_CAP_QOS`），完整实现待后续版本（与 DDS 演进阶段 2 的 QoS 策略
  语义衔接，见 DR-04）。
- **优先级**：P1
- **验收要点**：以 `docs/03-设计/核心模块/QoS框架设计.md` 为设计参考（注：该文档当前标注
  「部分过时」，实现时需重新校准）；DDS 阶段 2 落地时以 `test/test_dds_qos.c` 验证。

### FR-08 自动重连客户端

- **描述**：基于 `ssn_cliauto` 模块提供自动重连客户端：连接断开后自动重连、恢复订阅状态；对外
  提供稳定的消息收发接口，屏蔽断线期间的错误返回；回调线程安全，回调中不得执行关闭类操作。
- **优先级**：P1
- **验收要点**：`example_client`（8 例）通过；断线-重连场景在 `test_comprehensive` 中手工验证。

### FR-09 版本管理与错误码体系

- **描述**：统一版本管理（`ssn_version_get_string`、`SSN_VERSION_*` 宏，随 VERSION 文件/
  CMakeLists 发版同步）与错误码体系 `SSN_ECODE_*`：按分类组织（通用 COMMON / 网络 NETWORK /
  服务 SERVICE / 资源 RESOURCE / 安全 SECURITY / 序列化 SERIALIZE），如 `SSN_ECODE_SUCCESS`、
  `SSN_ECODE_TIMEOUT`、`SSN_ECODE_NET_CONNECT` 等；所有错误必须经日志记录
  （`LOG_ERROR`/`LOG_WARNING`）并统一返回。
- **优先级**：P0
- **验收要点**：`ssn_error.h` 错误码与文档一致；`examples/advanced/02_error_handling` 可运行；
  发版时 VERSION、`ssn_version.h`、`CMakeLists.txt`、CHANGELOG 四处同步。

## 3. 非功能需求

### NFR-01 性能

- **描述**：通信路径保持低开销：发送/接收路径避免不必要的锁竞争与数据拷贝（低拷贝路径）、支持
  非阻塞 I/O（EAGAIN 正确处理）、支持批量处理与多消息吞吐；零拷贝、内存池、连接池等为愿景优化
  方向（见白皮书第 8 章，不承诺当前版本实现）。
- **优先级**：P1
- **验收要点**：`test_stress` 压测可用（手工运行）；`test_transport` 全量通过。

### NFR-02 线程安全

- **描述**：`ssn_client`/`ssn_server` 采用引用计数 + 细粒度锁 + `valid` 状态标记保证并发安全；
  回调可能在其他线程执行，回调中不得调用 `ssn_client_close` 等销毁类操作；销毁路径不得自锁。
- **优先级**：P0
- **验收要点**：`test_thread_safety` 通过（手工运行）；设计细节见
  `docs/03-设计/核心模块/线程安全设计.md`。

### NFR-03 可移植性

- **描述**：遵循 C99 标准与 POSIX 接口，支持 Linux/macOS；编译要求 CMake ≥ 3.12、GCC ≥ 4.8
  （或 Clang ≥ 3.0）、pthread；Windows 用户经 WSL 构建与运行。
- **优先级**：P1
- **验收要点**：`bash test/run_tests.sh` 在 WSL 中构建 + 7 套件全部通过。

### NFR-04 可维护性

- **描述**：公开符号统一 `ssn_` 前缀、VSI 内部保留 `ipc_` 前缀；类型 `ssn_<module>_t`、函数
  `ssn_<module>_<action>`、宏 `SSN_UPPER_CASE`；函数 ≤ 200 行、行 ≤ 120 字符；使用
  clang-format 统一格式、cppcheck 静态分析；文档按编号目录组织，开发遵循 TDD 流程与分支/版本
  规范（见 `CLAUDE.md`）。
- **优先级**：P0
- **验收要点**：新增代码符合命名与风格规范；文档新增内容放入对应编号目录。

## 4. DDS 对标需求映射

### 4.1 对标背景与定位

对标 DDS 的根本目的是**学习 DDS**：以 DDS 的概念模型为参照，逐步设计、渐进靠近，将 SSN 从
「以连接为中心的 IPC 框架」演进为「以数据为中心的分布式通信框架」。SSN 采用**概念借鉴型**
定位：借鉴概念模型与关键机制，保持轻量 IPC 定位，不追求 OMG 规范全量实现、RTPS 线协议互操作
或与真实 DDS 实现兼容（详见 `docs/03-设计/DDS演进设计.md` 第 8 章「明确不做的事」）。

### 4.2 需求映射总览

| 编号 | 需求名称 | 所属阶段 | 目标版本 | DDS 对应概念 |
|------|---------|---------|---------|-------------|
| DR-01 | 域概念 | 阶段 1：DCPS 概念模型 | 2.4.0 | DomainParticipant → `ssn_domain_t` |
| DR-02 | 主题抽象 | 阶段 1：DCPS 概念模型 | 2.4.0 | Topic → `ssn_topic_t` |
| DR-03 | 发布者订阅者抽象 | 阶段 1：DCPS 概念模型 | 2.4.0 | Publisher/DataWriter、Subscriber/DataReader（发布端/订阅端） |
| DR-04 | QoS 策略子集 | 阶段 2：QoS 策略语义 | 2.5.0 | RELIABILITY/HISTORY/DEADLINE/LIFESPAN/PARTITION → `ssn_qos_t` |
| DR-05 | 发现增强 | 阶段 3：发现与高级特性 | 2.6.0 | SPDP/SEDP → 增强组播/目录发现 |
| DR-06 | 内容过滤 | 阶段 3：发现与高级特性 | 2.6.0 | ContentFilteredTopic → 简单通配/前缀过滤 |

### 4.3 阶段 1：DCPS 概念模型（目标版本 2.4.0）

#### DR-01 域概念

- **描述**：引入通信域入口 `ssn_domain_t`（对齐 DDS DomainId 概念），域内隔离、域间不互通；
  域对象聚合/管理底层 `ssn_node` 实例。
- **优先级**：P1
- **验收要点**：`test/test_dds_concept.c` 中多域隔离用例通过；`examples/dds/01_domain_topic`
  可运行。

#### DR-02 主题抽象

- **描述**：引入类型化主题 `ssn_topic_t`（名称 + 类型名占位，阶段 1 不实现 IDL 类型系统）；
  Topic 名称映射现有 URL 路径（`/topic` 语义），作为发布者与订阅者的唯一解耦点。
- **优先级**：P1
- **验收要点**：`test/test_dds_concept.c` 主题注册用例通过；现有 `ssn_node`/`ssn_pubsub` API
  零改动（回归验证）。

#### DR-03 发布者订阅者抽象

- **描述**：引入 `ssn_publisher_t`（数据写入，`ssn_publisher_write`）与 `ssn_subscriber_t`
  （回调式读取，`ssn_subscriber_subscribe`，Listener 风格）；底层复用现有 `ssn_node_publish` /
  `ssn_node_subscribe` 能力，实现发布者-订阅者匿名性（无需知道对方地址，由框架发现与路由）。
- **优先级**：P1
- **验收要点**：`test/test_dds_concept.c` 发布订阅往返用例通过。

### 4.4 阶段 2：QoS 策略语义（目标版本 2.5.0）

#### DR-04 QoS 策略子集

- **描述**：引进 DDS QoS 策略**语义**（非全量规范），以 `ssn_qos_t` 承载五种核心策略：
  RELIABILITY（RELIABLE 启用重试/确认，BEST_EFFORT 尽力发送）、HISTORY（KEEP_LAST(N) 环形
  缓冲缓存最近 N 条）、DEADLINE（约定周期内未收到数据触发超时监听回调）、LIFESPAN（帧头时间戳
  驱动的消息 TTL 丢弃）、PARTITION（URL 前缀命名空间 `/partition/topic`）；策略随
  `ssn_publisher_write` / `ssn_subscriber_subscribe` 传入，作为发布者-订阅者双方契约
  （两侧策略交集生效）。
- **优先级**：P2
- **验收要点**：`test/test_dds_qos.c`（可靠 vs 尽力、历史缓存条数、DEADLINE 触发、TTL 丢弃）
  通过；`examples/dds/02_qos` 可运行。

### 4.5 阶段 3：发现与高级特性（目标版本 2.6.0）

#### DR-05 发现增强

- **描述**：对齐 DDS 分层发现精髓：SPDP（参与者级，现有组播发现增强为「域内参与者公告」：域名 +
  节点能力广播）与 SEDP（端点级，主题/发布者/订阅者信息交换，订阅方自动发现匹配的发布方）；目标
  实现「新增节点零配置接入」的自动连接体验。
- **优先级**：P2
- **验收要点**：`test/test_dds_discovery.c` 动态加入/离开的自动发现用例通过；
  `examples/dds/03_discovery` 可运行。

#### DR-06 内容过滤

- **描述**：引入 ContentFilteredTopic 的轻量映射：订阅端过滤表达式（简单通配/前缀匹配，不实现
  完整 filter 语言），减少无关数据传输；同时将现有回调扩展为事件化（on_data_available /
  on_publication_matched 等）并支持简单 WaitSet。
- **优先级**：P2
- **验收要点**：过滤场景测试通过（阶段 3 验证计划）。

### 4.6 需求状态与验证

- 阶段 1 落地时同时补全 FR-06/FR-07 的设计落地差距（现有 QoS/发现设计文档标注「部分过时」，属
  阶段 1 实现补全范围，见 `DDS演进设计.md` 4.1）；
- 验证方式贯穿三阶段：每阶段新增 `test/test_dds_*.c` 单元测试与 `examples/dds/` 概念 demo，
  既有 7 套件 + `test/verify_examples.sh` 全量回归（概念层纯新增，不破坏现有 API）；
- 每阶段完成 bump 次版本（2.4.0 → 2.5.0 → 2.6.0），同步更新 VERSION / CHANGELOG / 白皮书。
