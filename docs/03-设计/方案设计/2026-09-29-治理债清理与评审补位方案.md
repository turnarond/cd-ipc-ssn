## 1. 背景

v3.0.0（C++17 多 Peer Node）实施计划共 11 个任务，代码已推进至任务 4（2026-09-22 停更），任务 5–11 未开始。盘点发现，在继续功能开发前存在四类已确认的治理债，若不先清理，将导致 CI 门禁失效、评审门禁缺失与对外文档持续腐败：

1. **CI 文档红灯**：`test/run_tests.sh` 实际运行 21 个自动化套件，文档守卫基线仍为 17 套件 / 765 例，`.github/workflows/ci.yml` 的文档一致性步骤必然失败；
2. **评审门禁缺口**：v3.0.0 设计文档状态仍为"待专家评审"，实施计划任务 2、任务 4 要求的评审点无书面结论，而代码已实施到任务 4；
3. **白皮书事实腐败**：版本历程中 v2.5.8 条目与 CHANGELOG 不符；白皮书 §11.3 路线表与 DDS 文档的目标版本号互相矛盾；
4. **发布流程缺口**：v2.6.0 已发布（提交 `0869791`）但未创建 Git tag，违反工程规范 §3.2。

2026-09-29 WSL 实测基线：`run_tests.sh` **21 个套件全部通过、0 失败**；`verify_exports.sh` 通过（157 个 `ssn_` 符号、29 个关键 API）。

## 2. 目标与非目标

### 2.1 目标

- 文档守卫基线与全部受护当前态文档同步到实测事实，本分支 CI 四项检查全绿；
- 以独立评审 pass 完成 v3.0.0 任务 1–4 的评审门禁，结论回写设计文档与实施计划；
- 更正白皮书 v2.5.8 事实错误，统一 DDS 三阶段目标版本号口径；
- 由维护者补打 v2.6.0 Git tag。

### 2.2 非目标（YAGNI）

- 不重写白皮书/需求分析以反映 v3.0.0 架构——该工作归属实施计划任务 11，本方案仅同步测试数字等事实口径；
- 不重构文档守卫、不扩充守卫规则种类，只做基线值变更与一处窄豁免；
- 不修改任何生产代码，不推进 v3.0.0 任务 5；
- 不代行 commit / push / tag，全部提交操作由维护者执行。

## 5. 变更集 1B：v3.0.0 任务 1–4 独立评审

### 5.1 评审原则

- 评审是与 authoring 分离的独立 pass（工程规范 §8.3），只产出问题清单，不在评审中修改功能代码；
- 发现 Critical 问题时单独提请维护者批准，按红—绿—重构独立修复，不与评审记录混提交。

### 5.2 评审对象

- 公共头：`include/ssn/node/Status.hpp`、`Types.hpp`、`Node.hpp`；
- 私有实现：`src/node/` 下 NodeImpl、PeerRegistry、PeerSession、EventQueue、PollDriver、NodeBackend、Message、Status、Types 共 9 对文件；
- 内部跨库接口：`src/transports/ssn_transport_async_internal.h/.c` 及 tcp/udp/unix 传输改动；
- 测试：`test_cpp_node_types.cpp`、`test_cpp_peer_registry.cpp`、`test_cpp_node_lifecycle.cpp`、`test_cpp_node_backend.cpp`。

### 5.3 评审维度

1. **规格符合性**：公共 API 签名、`NodeConfig` 字段、事件集合、驱动模式互斥语义与设计文档第 4–6 节逐条核对；
2. **ABI/可见性边界**：`sizeof(ssn::Node) == sizeof(void*)`、公共头不泄漏 STL/锁/线程/C 句柄；内部 connect 函数显式 default 可见性跨库链接但不安装、不标 `SSN_API`；`nm -D` 复核与 verify_exports 白名单口径；
3. **并发与锁**：锁序 NodeImpl → PeerRegistry → PeerSession；回调派发期不持内部锁；poll/wakeup/stop 竞态；stop 幂等、waitStopped 线程身份检查；
4. **代际 ID 正确性（任务 2 指定评审点）**：generation 递增与 UINT32 回绕边界——回绕后槽位复用是否可能让旧 ID 误命中；
5. **资源所有权**：fd、内存、线程在连接失败、断连、Node 销毁各路径的释放，无句柄/线程泄漏；
6. **错误契约与 TDD 证据**：Status/Result 一致、无异常作为正常控制流；四个测试是锁定契约还是与实现共生；计划要求但缺失的测试；
7. **整洁度**：职责单一、命名达意、DRY、函数 ≤200 行、行宽 ≤120。

### 5.4 产出与门禁回写

- 产出分级清单：**Critical**（阻塞合并）/ **Important**（v3.0.0 必修）/ **Minor**（记录）；每条含文件:行、问题、业务/技术根因、修复建议；
- 维护者拍板后，将结论回写设计文档头部"文档状态"（"评审通过"或"有条件通过 + 遗留项"），并在实施计划任务 2 步骤 5、任务 4 步骤 6 的评审点补书面结论；
- Critical/Important 的修复各走独立红绿循环并附回归测试。

### 5.5 评审结论（2026-09-29 执行）

评审方法按 §5.3 七维度执行，公共头、私有实现、内部接口、测试、CMake 与 `nm -D` 动态符号表实测全覆盖。结论：**有条件通过**，设计文档状态与实施计划任务 2/4 评审点已同步回写。

**Critical（1 项，已修复并回归）**

- C1 唤醒管道失效时后台模式 `stop()`/`waitStopped()` 挂死最长 24h：`PollDriver` 管道创建失败或读端 fd 超出 `FD_SETSIZE` 时静默退化，`pselect(24h)` 无法被唤醒；`backendReady()` 原为死代码无人检查。修复：`Node::create()` 检查 `driver.usable()` 拒绝不可用驱动（返回 `ResourceLimit`）、`pollOnce` 对不可用唤醒句柄快速失败；红—绿—重构落地，新增 6 断言（`test_cpp_node_lifecycle` 229→235）。断言基线随本变更同步 1153→1159（C++ 873→879），守卫与全部当前态文档已同批更新，§4.1 表中 1153 为 1A 执行时点值，提交口径以 1159 为准。

**Important（7 项，书面遗留决议）**

| # | 问题 | 归属 |

| I2 | 连接成功路径（含 UDP 立即成功）上报 `PeerConnected` 后句柄随 backend 析构被关闭，未移交 PeerSession | 任务 5 数据面落地时重构 |

**Minor（10 项，记录）**

代际回绕 ABA（2^32-1 次复用，已接受风险）；`noexcept` 函数内 `Status::error` 分配在 OOM 下 terminate；PollDriver pipe 未置 `O_CLOEXEC`（传输层 socket 同病，既有口径）；`connect()` 持锁做地址解析/socket 创建；后台模式 pollOnce 持续失败无退避刷日志；`callback_error` 无公共出口；`waitStopped()` 对 Created 节点永久阻塞未文档化；`unix_connect_finish` 复制 `unix_mark_connected` 逻辑且 unix 传输 `connection_count` 从不递增（既有问题，建议向传输层登记 Issue）；stop 后 pending_connects 残留至析构（无泄漏）；测试缺口（registry 并发、poll 负超时、FD_SETSIZE 边界、UDP 立即成功语义）。
