## 1. 背景与目标

现有 `ssn_node_t` 同时暴露内部字段、单个客户端句柄和单一 `peer_address`，调用方还需自行管理 create/start/poll/stop/destroy。现有 `SsnService` 与 `SsnClient` 已能满足常规 JSON RPC 和 PubSub 场景，但原始消息、双向通信、多 Peer 与自定义事件循环仍需直接使用底层 C API，并受回调持锁、单主动连接和裸指针生命周期约束。

本设计面向需要原始二进制消息、双向通信及自定义事件循环的高级用户，将 Node 层收敛为唯一公开的 C++17 API。目标是：

- 一个 Node 同时监听入站连接并维护多个主动连接；
- 提供外部 `poll()` 与可选后台线程两种一致的驱动模式；
- 用户回调不持有内部锁，允许安全重入；
- 以 RAII、PImpl 和统一错误模型约束资源与 ABI；
- 保留现有 client/server、frame、transport 等公开 C API，仅移除未被外部使用的旧 Node C API。

## 2. 范围与版本边界

### 2.1 本版本包含

- 公共 `ssn::Node`、配置、Peer、事件、消息和错误类型；
- 多 Peer 入站/出站连接管理；
- 原始消息单播与广播；
- 外部 poll、后台线程、跨线程唤醒和背压；
- `SsnService`、`SsnClient` 及 Node 示例向新核心迁移；
- 旧 `ssn_node_*` 的源码、安装项和导出符号清理。

### 2.2 本版本不包含

- Coroutine、Future、用户 Executor 或 Reactor 注入；
- 异步零拷贝发送及发送完成回调；
- 新 RPC/PubSub 协议能力；
- TLS/DTLS、自动重连策略、服务发现和 QoS 扩展；
- 对其他公开 C API 的收敛或不兼容修改。

该变更替换公开 Node 接口，采用 v3.0.0 主版本边界。现有 roadmap 中 v2.7.0～v2.9.0 已分配给 DDS 阶段，不与本重构混合交付。

## 3. 总体架构

```text
高级 SDK 用户
    ↓
ssn::Node（C++17、PImpl、move-only）
    ↓
私有 Node Engine（状态机、Peer 表、事件队列）
    ↓
现有 client/server、frame、transport、VSI
```

公共头文件新增于 `include/ssn/node/`。私有实现保留在 `src/node/`，不得被安装或由公共头文件引用。RPC 与 PubSub 采用独立适配器组合，首版继续由 `SsnService` 和 `SsnClient` 提供业务接口，不进入 `Node` 主类。

## 4. 公共 API

公共类型包括 `Node`、`NodeConfig`、`ListenAddress`、`ConnectOptions`、`PeerId`、`PeerInfo`、`NodeEvent`、`MessageView`、`Message`、`Status`、`Result<T>`、`NodeState`、`PeerState` 和 `ErrorCode`。

`Node` 不可复制、可以移动，公共类布局只持有 `std::unique_ptr<Impl>`。析构函数为 `noexcept`，自动请求停止并释放资源。主要操作如下：

- `Node::create(config)`：创建未启动实例，不执行网络或线程操作；
- `listen(address)`：在启动前添加 TCP 或 Unix Socket 监听地址；
- `connect(address, options)`：非阻塞发起连接并返回带代际信息的 `PeerId`；
- `disconnect(peer)`：非阻塞请求断开指定 Peer；
- `send(peer, bytes)`：复制数据后加入该 Peer 发送队列；
- `broadcast(bytes)`：为当前已连接 Peer 并逐个入队；
- `poll(timeout)`：由调用线程驱动一次 IO 与事件派发；
- `startBackground()`：启动内部事件线程；
- `stop()`：幂等请求停止，不等待当前事件线程；
- `waitStopped()`：等待完全停止；从事件线程调用返回 `WouldDeadlock`；
- `setEventHandler(handler)`：设置统一事件处理器；
- `peers()`、`peerInfo(peer)`：返回线程安全的只读快照。

第一次成功 `poll()` 或 `startBackground()` 确定驱动模式，实例生命周期内不得混用。首版不暴露底层 C 句柄。

## 5. 数据与事件所有权

接收事件携带 `MessageView`，它是仅在当前回调期间有效的只读零拷贝视图。需要跨线程或延迟处理时，用户必须调用 `MessageView::copy()` 获得拥有存储的 `Message`。

`send()` 和 `broadcast()` 在返回前复制调用方数据，调用方可立即释放原缓冲区。发送队列中的数据由 Node 独占管理。首版不提供借用发送缓冲区，避免引入完成通知、取消和跨线程引用计数语义。

`PeerId` 由槽位编号和代际组成。Peer 槽位复用时增加代际，所有操作都验证完整 ID，确保过期 ID 不会命中新连接。

## 6. 内部组件

- `NodeImpl`：实现 Node 状态机并协调各组件；
- `PeerRegistry`：维护 `PeerId → PeerSession`，生成代际 ID 和安全快照；
- `PeerSession`：拥有单个连接状态、底层句柄和发送队列；
- `EventQueue`：暂存连接、消息、错误和背压事件；
- `PollDriver`：承载唯一事件循环，实现外部与后台驱动的一致行为；
- `WakeupHandle`：唤醒正在等待的 poll，使跨线程发送、断开和停止及时生效。

锁获取顺序固定为 `NodeImpl → PeerRegistry → PeerSession`。状态更新在锁内完成，用户事件在相关锁全部释放后串行派发。Peer 删除分为标记 Closing、生成最终事件、派发完成后回收三个步骤。

## 7. 状态机与线程语义

Node 状态为：

```text
Created → Running → Stopping → Stopped
             ↓
           Failed
```

Peer 状态为：

```text
Connecting → Connected → Closing → Disconnected
      ↓           ↓
 ConnectFailed   Failed
```

外部模式的回调在 `poll()` 调用线程执行；后台模式的回调在 Node 专用事件线程执行。同一 Node 的回调始终串行且保持已接收事件的顺序。`send()`、`disconnect()` 和 `stop()` 可从其他线程调用，并通过 `WakeupHandle` 通知事件线程。

回调中允许调用非阻塞 `send()`、`disconnect()` 等 API。可能等待当前事件线程的操作不得阻塞：`poll()` 返回 `InvalidState`，`waitStopped()` 返回 `WouldDeadlock`。用户回调抛出的异常在 Node 边界捕获，转为 CallbackError 事件或日志，不允许异常穿越 C 调用边界或终止事件循环。

## 8. 错误模型

核心接口不以异常表达运行时失败：无返回值操作使用 `Status`，有返回值操作使用 `Result<T>`。错误至少包含稳定 `ErrorCode`、类别和用于诊断的文本。首版错误类别覆盖参数、状态、地址、连接、超时、IO、协议、资源上限、背压、回调和潜在死锁。

构造函数不申请可能失败的系统资源；`Node::create()` 负责报告初始化失败。Debug 构建可对编程错误断言，Release 构建仍返回明确错误。析构函数不抛异常。

## 9. 背压与资源上限

`NodeConfig` 必须提供单 Peer 发送队列上限、Node 总发送队列上限、单次 poll 最大事件数和最大 Peer 数。所有上限具有安全默认值，并允许显式调整。

队列达到高水位时生成一次 `BackpressureOn`；降至低水位后生成 `BackpressureOff`。超过硬上限时 `send()` 返回 `QueueFull`，不得无限增长或静默丢弃。一个慢 Peer 只阻塞自身发送队列，不得阻塞其他 Peer 的接收、发送和事件派发。

`stop()` 停止接收新连接和新发送，处理已形成事件，并在配置的关闭期限内尝试刷新发送队列；期限到达后关闭连接并释放缓冲区，不无限等待。

## 10. 迁移与删除策略

旧 Node C API 尚无仓库外部用户，因此不提供兼容层或 deprecated 周期。实施完成时：

- 删除 `src/node/ssn_node.h` 及全部 `ssn_node_*` 导出；
- 清理 CMake 安装规则与导出校验基线；
- 将旧 Node C 示例替换为 C++17 示例；
- 将 Node C 测试迁移为面向公共 C++ API 的测试；
- `SsnService` 与 `SsnClient` 改为组合新 `Node`，不暴露 `ssn_node_t*`；
- 其他公开 C API 的符号和行为保持不变。

迁移不得保留两套独立 Node 引擎。若迁移期间需要短期适配代码，只能存在于未发布的中间提交，并必须在版本交付前删除。

## 11. TDD 与验收

实施严格遵循“红—绿—重构”，每个阶段先建立失败测试。验收范围至少包括：

1. Node 与 Peer 的全部合法和非法状态转换；
2. 过期 `PeerId`、槽位复用和不存在 Peer；
3. 多 Peer 同时连接、入站与出站并存、双向单播、广播和独立断开；
4. 回调中发送、断开、停止请求及异常抛出；
5. 外部 poll 与后台线程的行为一致性；
6. 跨线程发送、停止竞争、重复停止和销毁；
7. 高低水位、硬上限、慢 Peer 隔离及大消息边界；
8. 连接失败、半开连接、对端异常退出和非法帧；
9. 反复创建销毁、连接风暴和长时间稳定性运行；
10. ASan/UBSan、可用环境下的 ThreadSanitizer，以及 FD、句柄、线程和内存泄漏；
11. 安装后的独立 C++17 消费工程；
12. 旧 `ssn_node_*` 符号消失，其他公开 C API 无意外变化。

## 12. 实施顺序与评审点

1. 公共类型、错误模型、Node/Peer 纯内存状态机；
2. 外部 poll 与单 Peer 原始消息闭环；
3. 多 Peer、入站/出站并存和代际 ID；
4. 发送队列、背压、跨线程唤醒；
5. 后台驱动与生命周期竞态加固；
6. `SsnService`、`SsnClient`、示例和文档迁移；
7. 删除旧 Node C API，执行完整发布验收。

公共 API、并发模型、多 Peer 核心完成和旧 API 删除前分别安排专家评审。任一阶段发现现有 client/server 无法在不破坏其公开 C ABI 的前提下承载多 Peer，应停止实施并重新评审边界，不得在适配层堆叠隐式全局状态。

## 13. 交付文档

代码交付必须同步更新架构白皮书、需求分析、架构总览、C++ API 使用手册、迁移指南、示例索引、导出符号说明和 CHANGELOG。v3.0.0 打包节点由维护者创建 Git tag，并在发布验收报告中记录构建、测试、ABI、稳定性和消费集成证据。
