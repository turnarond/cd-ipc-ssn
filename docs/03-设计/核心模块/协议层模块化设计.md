## 背景与目标

### 当前架构分析

当前代码结构：
```
ssn_client.c    - 混杂了RPC、订阅、消息发送功能
ssn_server.c    - 混杂了RPC方法注册、响应、发布功能
ssn_protocol.c  - 基础协议解析
```

**存在的问题**：
1. 协议逻辑与传输逻辑耦合在一起
2. 客户端/服务端代码臃肿，难以维护
3. RPC、发布订阅、消息三种协议混在一起
4. 无法灵活替换或扩展协议实现
5. 会话层（node）与协议层边界不清晰

### 目标

拆分出独立的协议层模块：
1. **RPC协议层** - 请求/应答模式
2. **发布订阅协议层** - 发布/订阅模式
3. **消息协议层** - 发送/接收模式

## 目标架构设计

### 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    应用程序层 (Application)                    │
├─────────────────────────────────────────────────────────────┤
│                    节点抽象层 (Node Abstraction)              │
├─────────────────────────────────────────────────────────────┤
│                    协议层 (Protocol Layer)                    │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│  │  RPC协议   │  │ PubSub协议  │  │  MSG协议    │        │
│  │  (req/rep) │  │  (pub/sub)  │  │  (send/recv)│        │
│  └─────────────┘  └─────────────┘  └─────────────┘        │
├─────────────────────────────────────────────────────────────┤
│                    传输层 (Transport Layer)                  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│  │    TCP     │  │    UDP     │  │    Unix    │        │
│  └─────────────┘  └─────────────┘  └─────────────┘        │
└─────────────────────────────────────────────────────────────┘
```

### 模块划分

```
src/
  protocol/
    ssn_protocol.h           # 公共协议定义
    ssn_protocol.c           # 协议基础实现
    
  protocol/
    rpc/
      ssn_rpc.h              # RPC协议接口
      ssn_rpc.c              # RPC协议实现 (req/rep)
    
    pubsub/
      ssn_pubsub.h           # 发布订阅协议接口
      ssn_pubsub.c           # 发布订阅协议实现 (pub/sub)
    
    msg/
      ssn_msg.h              # 消息协议接口
      ssn_msg.c              # 消息协议实现 (send/recv)
```

## 协议层详细设计

### 1. 公共协议基础

#### 1.1 协议类型枚举

```c
/**
 * @brief 协议类型枚举
 */
typedef enum {
    SSN_PROTOCOL_RPC = 0,      // RPC请求-应答协议
    SSN_PROTOCOL_PUBSUB,       // 发布-订阅协议
    SSN_PROTOCOL_MSG           // 点对点消息协议
} ssn_protocol_type_t;
```

#### 1.2 协议上下文基类

```c
/**
 * @brief 协议上下文基类
 */
typedef struct ssn_protocol_ctx {
    ssn_protocol_type_t type;      // 协议类型
    ssn_transport_t *transport;    // 底层传输
    void *user_data;               // 用户数据
} ssn_protocol_ctx_t;

/**
 * @brief 协议操作接口
 */
typedef struct ssn_protocol_ops {
    // 协议初始化
    int (*init)(ssn_protocol_ctx_t *ctx, ssn_transport_t *transport);
    
    // 协议销毁
    void (*destroy)(ssn_protocol_ctx_t *ctx);
    
    // 发送数据
    int (*send)(ssn_protocol_ctx_t *ctx, const void *data, size_t len);
    
    // 接收数据
    int (*recv)(ssn_protocol_ctx_t *ctx, void *buffer, size_t size, int timeout_ms);
    
    // 获取协议类型
    ssn_protocol_type_t (*get_type)(ssn_protocol_ctx_t *ctx);
} ssn_protocol_ops_t;
```

### 2. RPC协议层（req/rep）

#### 2.1 RPC上下文结构

```c
/**
 * @brief RPC协议上下文 - 请求端（客户端）
 */
typedef struct ssn_rpc_req_ctx {
    ssn_protocol_ctx_t base;           // 基类
    
    // 待处理请求管理
    ssn_rpc_pending_t *pending_table; // 待处理请求表
    uint16_t next_seqno;              // 下一个序列号
    
    // 回调函数
    ssn_rpc_reply_handler_t on_reply; // 收到应答回调
    void *user_arg;                   // 用户参数
} ssn_rpc_req_ctx_t;

/**
 * @brief RPC协议上下文 - 应答端（服务端）
 */
typedef struct ssn_rpc_rep_ctx {
    ssn_protocol_ctx_t base;           // 基类
    
    // RPC方法表
    ssn_rpc_method_t *method_table;    // RPC方法注册表
    size_t method_count;               // 方法数量
    
    // 回调函数
    ssn_rpc_handler_t on_request;      // 收到请求回调
    void *user_arg;                    // 用户参数
} ssn_rpc_rep_ctx_t;
```

#### 2.2 RPC API

```c
/**
 * @brief 创建RPC请求端上下文（客户端用）
 *
 * @param on_reply 收到应答的回调函数

SSN_API ssn_rpc_req_ctx_t *ssn_rpc_req_create(

/**
 * @brief 创建RPC应答端上下文（服务端用）
 *

 * @return RPC应答端上下文，失败返回NULL
 */
SSN_API ssn_rpc_rep_ctx_t *ssn_rpc_rep_create(
    ssn_rpc_handler_t on_request,
    void *arg);

/**
 * @brief 绑定RPC应答端到传输层
 *
 * @param ctx RPC应答端上下文
 * @param transport 传输层实例
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_rpc_rep_bind(ssn_rpc_rep_ctx_t *ctx, ssn_transport_t *transport);

/**
 * @brief 连接RPC请求端到传输层
 *
 * @param ctx RPC请求端上下文
 * @param transport 传输层实例
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_rpc_req_connect(ssn_rpc_req_ctx_t *ctx, ssn_transport_t *transport);

/**
 * @brief 注册RPC方法
 *
 * @param ctx RPC应答端上下文
 * @param method_name 方法名
 * @param handler 方法处理函数
 * @param arg 用户参数
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_rpc_rep_register(
    ssn_rpc_rep_ctx_t *ctx,
    const char *method_name,
    ssn_rpc_handler_t handler,
    void *arg);

/**
 * @brief 发送RPC请求
 *
 * @param ctx RPC请求端上下文
 * @param method_name 方法名
 * @param data 请求数据
 * @param data_len 数据长度
 * @param timeout_ms 超时时间
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_rpc_req_call(
    ssn_rpc_req_ctx_t *ctx,
    const char *method_name,
    const void *data,
    size_t data_len,
    uint64_t timeout_ms);

/**
 * @brief 发送RPC响应
 *
 * @param ctx RPC应答端上下文
 * @param seqno 请求序列号
 * @param status 状态码
 * @param data 响应数据
 * @param data_len 数据长度
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_rpc_rep_response(
    ssn_rpc_rep_ctx_t *ctx,
    uint16_t seqno,
    uint32_t status,
    const void *data,
    size_t data_len);

/**
 * @brief 销毁RPC上下文
 *
 * @param ctx RPC上下文
 */
SSN_API void ssn_rpc_destroy(ssn_protocol_ctx_t *ctx);
```

## 统一的协议工厂

### 协议工厂API

```c
/**
 * @brief 协议类型与角色
 */
typedef enum {
    SSN_ROLE_REQ,    // RPC请求端（客户端）
    SSN_ROLE_REP,    // RPC应答端（服务端）
    SSN_ROLE_SEND,   // 消息发送端（客户端）
    SSN_ROLE_RECV,   // 消息接收端（服务端）
    SSN_ROLE_PUB,    // 发布端（服务端）
    SSN_ROLE_SUB     // 订阅端（客户端）
} ssn_role_t;

/**
 * @brief 创建协议上下文（根据角色）
 *
 * @param role 角色类型
 * @param callback 回调函数（用于需要回调的角色）
 * @param arg 用户参数
 * @return 协议上下文，失败返回NULL
 */
SSN_API ssn_protocol_ctx_t *ssn_protocol_create(
    ssn_role_t role,
    void *callback,
    void *arg);

/**
 * @brief 绑定/连接协议到传输层
 *
 * @param ctx 协议上下文
 * @param transport 传输层实例
 * @param is_server 是否为服务端
 * @return 成功返回0，失败返回-1
 */
SSN_API int ssn_protocol_bind(
    ssn_protocol_ctx_t *ctx,
    ssn_transport_t *transport,
    bool is_server);

/**
 * @brief 获取协议类型
 *
 * @param ctx 协议上下文
 * @return 协议类型
 */
SSN_API ssn_protocol_type_t ssn_protocol_get_type(ssn_protocol_ctx_t *ctx);

/**
 * @brief 销毁协议上下文
 *
 * @param ctx 协议上下文
 */
SSN_API void ssn_protocol_destroy(ssn_protocol_ctx_t *ctx);
```

## 使用示例

### 示例1：RPC请求-应答

```c
// 服务端
ssn_rpc_rep_ctx_t *rep = ssn_rpc_rep_create(on_request, NULL);
ssn_transport_t *transport = ssn_transport_create(SSN_TRANSPORT_TCP, NULL);
ssn_transport_listen(transport, "tcp://0.0.0.0:8080", 10);
ssn_rpc_rep_bind(rep, transport);

ssn_rpc_rep_register(rep, "add", handle_add, NULL);

// 客户端
ssn_rpc_req_ctx_t *req = ssn_rpc_req_create(on_reply, NULL);
ssn_transport_t *transport = ssn_transport_create(SSN_TRANSPORT_TCP, NULL);
ssn_transport_connect(transport, "tcp://127.0.0.1:8080", 5000);
ssn_rpc_req_connect(req, transport);

ssn_rpc_req_call(req, "add", &a, sizeof(a), 1000);
```

### 示例2：发布-订阅

```c
// 发布端
ssn_pubsub_pub_ctx_t *pub = ssn_pubsub_pub_create();

ssn_transport_listen(transport, "udp://0.0.0.0:9090", 10);
```

## 向后兼容性

### 保持现有API兼容

```c
// 旧API仍然支持
ssn_server_create("tcp://0.0.0.0:8080");
ssn_client_connect(client, "unix:///tmp/test.sock", &timeout);
ssn_client_call(client, &url, &data, callback, arg, timeout_ms);
ssn_server_publish(server, &url, &data);

// 新API提供更模块化的接口
ssn_protocol_create(SSN_ROLE_REQ, callback, arg);
ssn_rpc_req_call(req, "method", data, len, timeout_ms);
```

## 注意事项

1. **线程安全**：协议层本身不是线程安全的，需要调用方保证同步
2. **内存管理**：协议上下文创建后需要调用对应destroy函数释放
3. **传输层依赖**：协议层依赖于底层传输层，需要先创建传输层
4. **回调函数**：回调函数在收到数据时被调用，需要快速返回避免阻塞

## 总结

通过将协议层拆分为独立的RPC、发布订阅和消息三个模块：

1. **职责清晰**：每个协议模块职责单一，易于维护
2. **可扩展性强**：可以独立扩展或替换某个协议实现
3. **代码复用**：公共协议基础代码被复用
4. **易于测试**：每个模块可以独立进行单元测试
5. **灵活组合**：用户可以选择使用哪些协议，传输层也可以灵活选择

这套设计实现了协议层与传输层的完全解耦，让用户可以灵活组合使用。
