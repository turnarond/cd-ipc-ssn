# SSN C++ 服务框架：一行启动你的 IPC 服务

> 面向：希望快速用 C++ 开发 IPC 服务的开发者。
> 本文基于 SSN v2.5.1 的 C++ 服务框架（`libssn_framework.so`，C++17）。
> 目标：**30 秒跑通第一个服务**。

## 1. 为什么需要一层 C++ 封装

SSN 的 C API（`ssn_node_t` / `ssn_client_t`）功能完整，但使用成本高：

- 需要手工管理节点生命周期（create/start/stop/destroy）
- 需要自行驱动 poll 事件循环
- 需要手写 JSON 编解码与错误处理

C++ 服务框架在这些能力之上做了一层「面向服务开发」的封装：

| 能力 | C API | C++ 框架 |
|------|-------|----------|
| 生命周期 | 手工 4 步 | `ServiceManager::Run<T>()` 一行 |
| 事件循环 | 自己写 poll 循环 | 内部线程自动驱动 |
| 方法注册 | 手工 URL 匹配 | `RegisterMethod<Req,Resp>` 直接映射 |
| 管理接口 | 无 | 内置 `/urls` `/health` `/version` |
| 类型安全 | 无（void*） | 编译期 DTO 检查 |

## 2. 30 秒跑通 Echo 服务

### 2.1 服务端（一个文件，约 40 行）

```cpp
#include "ssn/framework/ServiceManager.hpp"
#include "ssn/framework/SsnService.hpp"

#include <iostream>
#include <nlohmann/json.hpp>

// 服务定义：继承 SsnService，构造函数中完成「监听 + 注册方法」配置
class EchoService : public ssn::SsnService {
public:
    EchoService() {
        // 监听配置：TCP 地址 127.0.0.1:18880（必须在服务初始化前调用）
        listenTcp("127.0.0.1", 18880);

        // 注册 RPC 方法：URL 即服务接口名；handler 收到请求 JSON，返回应答 JSON
        registerJson("/echo", [](const nlohmann::json& req) -> nlohmann::json {
            return req;   // echo 语义：请求是什么，应答就是什么
        });
    }

    // 初始化钩子：基类 OnInit 完成后服务端已真实监听，此时打印启动信息
    bool OnInit(int argc, char** argv) override {
        if (!ssn::SsnService::OnInit(argc, argv)) {
            return false;
        }
        std::cout << "Echo 服务已启动，监听 tcp://" << listenHost() << ":"
                  << listenPort() << "（Ctrl+C 优雅退出）" << std::endl;
        return true;
    }
};

int main(int argc, char** argv) {
    // 一行启动：完整生命周期由 ServiceManager 编排，收到信号后自动优雅退出
    return ssn::ServiceManager::Run<EchoService>(argc, argv);
}
```

编译运行：

```bash
g++ -std=c++17 -I include -I src -I third_party -o echo_server echo_server.cpp \
    -L build -lssn_framework -lssn_transport -lpthread -Wl,-rpath,$PWD/build
./echo_server
```

输出：

```
Echo 服务已启动，监听 tcp://127.0.0.1:18880（Ctrl+C 优雅退出）
```

> 以上代码即 `examples/cpp/01_echo_service/echo_server.cpp` 的真实内容（约 40 行）。
> 如需**类型安全**方法注册（handler 收到强类型 DTO 而非裸 JSON），见第 3 节
> `RegisterMethod<Req, Resp>` 用法。

### 2.2 客户端（同步调用）

```cpp
#include "ssn/framework/SsnClient.hpp"

#include <iostream>
#include <nlohmann/json.hpp>

int main() {
    ssn::SsnClient cli;
    if (!cli.connect("tcp://127.0.0.1:18880")) {
        std::cerr << "连接失败" << std::endl;
        return 1;
    }

    nlohmann::json req = {{"msg", "你好，SSN C++ 框架！"}};
    nlohmann::json resp;
    if (cli.callJson("/echo", req, resp)) {
        std::cout << "应答: " << resp.dump() << std::endl;
    } else {
        std::cerr << "调用失败" << std::endl;
        cli.disconnect();
        return 1;
    }
    cli.disconnect();
    return 0;
}
```

> 注：`connect` 仅创建并启动客户端节点（不接触服务器），实际连接发生在首次
> `callJson`——服务端未启动时 `connect` 仍返回 true，`callJson` 返回 false。

### 2.3 一键体验

```bash
cd examples/cpp/01_echo_service

```

## 3. 三大亮点

### 亮点 1：类型安全 RPC（编译期检查）

`RegisterMethod<Req, Resp>` 的 handler 收到反序列化后的 `Req` 对象，返回值必须是
`Resp`（不匹配**编译失败**）；客户端 `Call<Req, Resp>` 同样类型安全：

```cpp
// 侵入式宏必须写在结构体内部（注入 to_json/from_json 实现）
struct JoinReq {
    std::string nickname;
    NLOHMANN_DEFINE_TYPE_INTRUSIVE(JoinReq, nickname)
};
struct JoinResp {
    bool ok;
    std::string welcome;
    int member_count;
    NLOHMANN_DEFINE_TYPE_INTRUSIVE(JoinResp, ok, welcome, member_count)
};

RegisterMethod<JoinReq, JoinResp>("/chat/join", [](const JoinReq& req) {
    return JoinResp{true, "欢迎 " + req.nickname, 2};
});
```

DTO 与 JSON 的互相转换由 nlohmann/json 自动完成——字段缺失/类型不符会返回框架
错误码 1003（handler 异常），服务不崩溃。

### 亮点 2：内置管理端点

每个服务自动提供：

| 端点 | 内容 |
|------|------|
| `/urls` | 已注册方法列表 `{"urls":["/echo","/health","/urls","/version"]}` |
| `/health` | 健康状态、连接数、消息数 `{"status":"ok","connections":0,"messages":0}` |
| `/version` | 框架版本 `{"version":"2.5.1"}` |

无需额外开发，运维/监控开箱即用。

### 亮点 3：优雅停止 + 稳定性设计

- **信号处理**：`Run<T>` 安装 SIGINT/SIGTERM 处理器，`Ctrl+C` 优雅停止（先 stop 后
  destroy），返回前还原信号状态（可重复 Run）；
- **回调异常保护**：handler 抛任何异常都被捕获，按 1003 应答——服务不会因单个
  方法异常而崩溃；
- **失败可观测**：svc 线程异常退出时 `/health` 状态变为 `degraded`，服务「假活」
  可被监控发现；
- **并发约束文档化**：同一客户端并发调用被串行化（多并发请用多个实例）；
  回调内不得调用会加锁的 API（防死锁）——这些约束在头文件注释中明确写出。

## 5. 已知限制（如实标注）

- 仅 TCP 监听（`listenTcp`；框架层未暴露 Unix Domain Socket 配置）
- 同一 `SsnClient` 并发调用串行化（需要并行请拆多个实例）
- 客户端 connect 的 C 层连接超时固定 3 秒
- 错误码 1004（客户端超时）不产生错误应答体，超时仅表现为返回 false
