## 一、基础概念

### IPC（进程间通信）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 进程间通信（Inter-Process Communication）。SSN 是基于 C99 的高性能 IPC 框架，提供 RPC、发布/订阅、点对点消息三种通信能力，运行于 Unix Domain Socket / TCP / UDP 之上 |
| 相关文档 | [架构白皮书](../01-白皮书/架构白皮书.md)、[使用指南](使用指南.md)「1. 概述」 |

### 节点（Node）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | `ssn_node_t` 是节点抽象层提供的高级封装，同时具备客户端与服务器能力（create / start / stop / destroy），支持节点间消息、RPC 与订阅，是「数据为中心」演进的基础 |
| 相关文档 | [使用指南](使用指南.md)「3.2 节点抽象」「4.4 节点 API」、[节点抽象设计](../03-设计/核心模块/节点抽象设计.md) |

### 域（Domain）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 借鉴 DDS 的概念：通信域，域内参与者互相可见、域间隔离（对齐 DDS DomainId 概念）。当前为设计演进概念（`ssn_domain_t`，阶段 1），尚未落地实现 |
| 相关文档 | [DDS 演进设计](../03-设计/DDS演进设计.md)「DCPS 概念模型」、[需求分析](../02-需求分析/需求分析.md) |

## 二、通信模式

### RPC（远程过程调用）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 请求-响应式同步通信：客户端 `ssn_client_call` 发起调用，服务器通过 `ssn_server_add_method` 注册方法并在回调中经 `ssn_server_response` 返回结果；响应超时或失败时回调的 `ipc_hdr` 为 NULL，携带状态码 `ssn_ecode_t` |
| 相关文档 | [使用指南](使用指南.md)「5.2 RPC 调用」「6. 错误处理」、[通信模式教程](通信模式教程.md)「REQ/REP」 |

### PubSub（发布/订阅）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 一对多消息分发模式：发布端 `ssn_server_publish` 按主题发布，订阅端 `ssn_client_subscribe` 按主题订阅并回调；同一主题可多订阅者，`ssn_server_is_subscribed` 可查询主题订阅状态 |
| 相关文档 | [使用指南](使用指南.md)「5.3 发布/订阅」、[通信模式教程](通信模式教程.md)「PUB/SUB」 |

### Topic（主题）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 消息的路由标识，即 URL 路径字符串（如 `/news`），发布与订阅方必须使用完全一致的路径；主题与订阅注册表由协议层 `ssn_pubsub` 管理 |
| 相关文档 | [使用指南](使用指南.md)「3.3 通信模式」「3.4 数据与 URL 引用」、[协议层模块化设计](../03-设计/核心模块/协议层模块化设计.md) |

### 消息（Message）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 普通点对点消息，通过 `ssn_client_message`/`ssn_server_message` 发送，无内置队列、重试与 ACK（任务分发等语义需应用层实现）；消息类型由 `SSN_MSG_TYPE_*` 定义（RPC 请求、订阅、发布、普通消息、心跳 PING_ECHO 等） |
| 相关文档 | [通信模式教程](通信模式教程.md)「PUSH/PULL」「4.3 常见坑」、[API 使用指南](API使用指南.md)「消息类型」 |

## 三、地址与传输

### URL（地址格式）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 统一为 `协议://地址` 格式（`ssn_address_parse` 要求地址含 `://`）：`unix:///path`、`tcp://host:port`、`udp://host:port`。仅服务端创建对裸路径自动补全 `unix://`，客户端连接必须写全前缀 |
| 相关文档 | [使用指南](使用指南.md)「3.1 传输协议」、[API 使用指南](API使用指南.md)「地址格式」 |

### 传输（Transport）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 传输层（`ssn_transport_t` + 工厂）抽象 Unix Socket（本地最快）、TCP（可靠、面向连接）、UDP（无连接、尽力而为）三类传输；UDP 不支持 server 模式握手，仅适用于客户端模式点对点收发 |
| 相关文档 | [传输层设计](../03-设计/架构设计/传输层设计.md)、[部署手册](../05-部署手册/部署手册.md)「4.3 UDP server 握手限制」 |

### 线协议（Wire Protocol）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 消息在线上传输的字节格式，由 `ssn_frame`（`src/ssn_frame.c`）统一完成帧编解码，协议层（rpc/pubsub/msg）的收发包均经其序列化；与 RTPS 等标准线协议无互操作（DDS 演进不追求） |
| 相关文档 | [架构白皮书](../01-白皮书/架构白皮书.md)「协议层」、[协议层模块化设计](../03-设计/核心模块/协议层模块化设计.md) |

### 帧（Frame）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 线协议中的一个完整数据包，头结构为 `ssn_header_t`（含类型、seqno、状态、负载长度等字段），通过 `ssn_get_status`/`ssn_get_seqno` 等访问；单包上限 128 KiB（`SSN_MAX_PACKET_SIZE`），大消息需应用层分片 |
| 相关文档 | [API 使用指南](API使用指南.md)「回调函数」、[使用指南](使用指南.md)「7.3 内存管理」 |

## 四、事件与回调

### 事件循环（Event Loop）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 单线程轮询模型：`ssn_server_poll`/`ssn_client_poll`（timeout 毫秒）单次轮询或 `ssn_server_run`/`ssn_client_run` 阻塞运行；库不自动驱动，连接握手、消息分发、超时断开均需 poll 活跃（全局定时器线程仅负责 idle/握手计时） |
| 相关文档 | [部署场景指南](../05-部署手册/部署场景指南.md)「4.2 事件循环驱动」、[使用指南](使用指南.md)「4.2 客户端 API」 |

### 回调（Callback）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 事件驱动的处理函数：消息回调（`ssn_client_msg_handler_t`）、RPC 回调（`ssn_client_rpcreply_handler_t`/`ssn_server_rpc_handler_t`）、连接回调（`ssn_on_connect_t`）等；回调可能在其他线程执行，回调中不得调用 `ssn_client_close`/`ssn_server_destroy`，参数指针（url/data）仅在回调返回前有效 |
| 相关文档 | [API 使用指南](API使用指南.md)「回调函数」、[线程安全设计](../03-设计/核心模块/线程安全设计.md) |

## 五、数据与接口

### DTO（数据传输对象）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 跨进程传递的业务数据结构。SSN 以字节序列形式传输（`ssn_data_ref_t` 承载负载），不强制序列化格式——RPC 参数/响应可由应用自行定义（示例中常用 JSON 文本），序列化失败对应 `SSN_ECODE_SERIALIZE_FAILED` 等错误码 |
| 相关文档 | [使用指南](使用指南.md)「3.4 数据与 URL 引用」「6.1 错误码」 |

### stub/代理（Stub/Proxy）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | RPC 概念中客户端侧代理与服务器侧存根，负责参数打包/结果解包。SSN 当前不提供代码生成 stub，RPC 调用直接以 URL + 数据引用 + 回调完成（`ssn_client_call`/`ssn_server_add_method`），由应用层负责序列化约定 |
| 相关文档 | [通信模式教程](通信模式教程.md)「REQ/REP」、[使用指南](使用指南.md)「5.2 RPC 调用」 |

### QoS（服务质量）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 服务质量配置模型：当前已实现基础框架（可靠性、优先级、带宽配置模型与接口，v2.0.0 起，能力位 `SSN_NODE_CAP_QOS`）；DDS 演进阶段 2 将引入 RELIABILITY/HISTORY/DEADLINE/LIFESPAN/PARTITION 五种策略语义（`ssn_qos_t`，目标 2.5.0），当前未完整落地 |
| 相关文档 | [架构白皮书](../01-白皮书/架构白皮书.md)「6. QoS 支持框架」、[QoS 框架设计](../03-设计/核心模块/QoS框架设计.md)、[DDS 演进设计](../03-设计/DDS演进设计.md)「阶段 2」 |

## 六、生命周期与可靠性

### 握手（Handshake）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 客户端连接服务器后的建链确认过程：服务器通过 poll 轮询响应握手，握手完成后触发连接回调（`ssn_on_connect_t`，connect=true）并开始 idle 计时；UDP 无连接传输不支持 server 模式握手 |
| 相关文档 | [部署场景指南](../05-部署手册/部署场景指南.md)「4.2」「4.3」、[部署手册](../05-部署手册/部署手册.md)「4.3」 |

### 心跳/Keepalive

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 两类保活机制：客户端侧应用层 ping 心跳（`ssn_client_auto` 的 keepalive 参数，间隔毫秒，最小 50ms，消息类型 `SSN_MSG_TYPE_PING_ECHO`）；服务器侧 TCP 层保活（SO_KEEPALIVE，用于检测物理断链），两者相互补充 |
| 相关文档 | [使用指南](使用指南.md)「4.5 自动重连客户端」「7.1 连接管理」、[部署场景指南](../05-部署手册/部署场景指南.md)「4.3」 |

### idle 超时（空闲超时）

| 项目 | 内容 |
|------|------|
| 定义（SSN 语境） | 服务端对已握手连接的应用层空闲断开机制：默认 10 秒（`IPC_SERVER_KEEPALIVE_TIMEOUT`），可用 `server_options_t.idle_timeout_sec` 覆盖（≤0 禁用）；连接每次收包自动重置计时，idle 断开路径不触发断开回调 |
| 相关文档 | [部署场景指南](../05-部署手册/部署场景指南.md)「4.3 idle / keepalive 行为说明」、[使用指南](使用指南.md)「4.3 服务器 API」 |
