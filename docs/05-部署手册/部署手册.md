## 1. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux/POSIX（含 macOS）；仅支持 Linux/POSIX，产物为动态库 `libssn_transport.so` |
| Windows | 不支持原生构建，请使用 WSL（见 4.2） |
| CMake | ≥ 3.12 |
| 编译器 | C 库：GCC ≥ 4.8（或 Clang ≥ 3.0）；**C++ 服务框架（libssn_framework.so）：GCC ≥ 7 / Clang ≥ 6（C++17）** |
| 依赖库 | pthread |
| 语言标准 | C99（`CMAKE_C_STANDARD 99`）；C++17（`cxx_std_17`，仅框架库） |

## 2. 构建

### 2.1 构建库

```bash
mkdir -p build && cd build
cmake ..
make -j$(nproc)
```

构建产物：`build/libssn_transport.so`（动态库，SOVERSION 为 `libssn_transport.so.2`）。

### 2.2 构建并运行测试

一键验证脚本（构建 + 13 个自动化套件，全部通过后退出码为 0）：

```bash
bash test/run_tests.sh
```

自动化套件清单：C 侧 7 个——`test_transport`（55 例）、`test_node_basic`（3 例）、`test_node`
（6 例）、`test_protocol`（25 例）、`test_protocol_integration`（19 例）、`example_server`
（8 例）、`example_client`（9 例），共 125 例；C++ 框架 6 个——`test_cpp_service_base`（41）、
`test_cpp_service_task`（12）、`test_cpp_service_manager`（6）、`test_cpp_ssn_service`（76）、
`test_cpp_ssn_client`（24）、`test_cpp_json`（11）、`test_cpp_stability`（286），共 456 例。合计 14 套件 581 例。

高级/手工测试（需先手工启动服务端，可用于性能与并发验证）：

```bash
./test_comprehensive   # 综合测试
./test_thread_safety   # 线程安全测试
./test_stress          # 压力测试
```

### 2.3 构建示例

全部 19 个示例构建验证：

```bash
bash test/verify_examples.sh
```

示例位于 `examples/basic/`（hello/rpc/pubsub/node_basic）、`examples/advanced/`（多线程/错误
处理/超时/传输选择）、`examples/protocols/`（unix/tcp/udp）、`examples/node/`（节点生命周期/
通信/RPC/发布订阅）、`examples/cpp/`（C++ 服务框架：echo 服务、pubsub 聊天）。

### 2.4 运行示例

示例 Makefile 已内置 rpath（`-Wl,-rpath,$(TOP_DIR)/build`）指向构建产物目录，构建后可直接执行，
无需设置 `LD_LIBRARY_PATH`：

```bash
cd examples/basic/01_hello_world
make            # 构建 server/client
./server &      # 终端 1：启动服务端
./client        # 终端 2：运行客户端
```

UDP 示例支持一键运行：`cd examples/protocols/03_udp && make run`（注意 UDP 服务端握手限制，
见 4.3）。

## 3. 安装与集成

### 3.1 安装

```bash
cd build
make install              # 默认安装到 /usr/local（CMake ≥ 3.12 均可）
# 或指定前缀：
cmake --install . --prefix /usr/local    # 需 CMake ≥ 3.15
```

安装内容：

- `lib/`：`libssn_transport.so`（含符号链接 `libssn_transport.so.2`、`libssn_transport.so.2.4.x`）
  与 `libssn_framework.so`（C++ 服务框架，v2.4.0）
- `include/`：公开头文件（清单见 3.2）

### 3.2 头文件清单

`cmake --install` 安装的公开头文件（位于 `include/`，由 CMakeLists.txt 的 install 规则定义）：

| 头文件 | 用途 |
|--------|------|
| `ssn_export.h` | 导出宏定义 |
| `ssn_version.h`（及 `version/ssn_version.h`） | 版本信息（`SSN_VERSION_*` 宏、`ssn_version_get_string`） |
| `ssn_transport.h`（及 `transports/ssn_transport.h`） | 传输层统一接口与工厂 |
| `ssn_client.h` | 客户端 API |
| `ssn_server.h` | 服务端 API |
| `ssn_frame.h` | 线协议（`ssn_header_t`） |
| `ssn_cliauto.h` | 自动重连客户端 API |
| `ssn_log.h`（及 `util/ssn_log.h`） | 日志接口 |
| `ssn_mutex.h`（及 `util/ssn_mutex.h`） | 互斥锁工具 |
| `ssn_hash_table.h`（及 `util/ssn_hash_table.h`） | 哈希表工具 |
| `node/ssn_node.h` | 节点抽象层（服务端+客户端双角色） |
| `ssn_error.h` | 错误码（`SSN_ECODE_*`） |
| `ssn_global.h`（及 `vsi/ipc_platform.h`） | 内部全局状态与平台定义（引用链依赖） |
| `nlohmann/json.hpp` | nlohmann/json v3.11.3（MIT，C++ 框架 DTO 序列化依赖） |
| `ssn/framework/*.hpp` | C++ 服务框架公共头（ServiceBase/ServiceTask/ServiceManager/SsnService/SsnClient） |

> 说明：`ssn_transport.h`、`ssn_log.h` 等头文件同时安装顶层扁平路径与镜像源码树的
> 子目录路径（如 `transports/`、`util/`、`version/`）——源码头文件以相对路径互相引用
> （如 `ssn_frame.h` → `transports/ssn_transport.h`），子目录路径是安装后可直接编译
> 的前提，顶层路径保留向后兼容。包含头文件时建议使用与源码一致的子目录路径。

### 3.3 链接

```bash
# 编译并链接（以安装到 /usr/local 为例）
gcc -std=c99 -I/usr/local/include app.c -L/usr/local/lib -lssn_transport -lpthread -o app
```

链接参数：`-lssn_transport -lpthread`。

### 3.4 CMake 集成（find_package）

安装后自带 CMake 包配置（`lib/cmake/ssn/ssnConfig.cmake`），CMake 项目可直接：

```cmake
find_package(ssn REQUIRED)

add_executable(app main.c)
target_link_libraries(app PRIVATE ssn::ssn_transport)

# C++ 服务框架：
add_executable(svc main.cpp)
target_link_libraries(svc PRIVATE ssn::ssn_framework)   # 自动传递 ssn::ssn_transport
```

配置时指定安装前缀（未装到系统路径时）：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/path/to/install
```

完整可运行消费示例见 `examples/cmake_integration/`（C 库 + C++ 框架双消费者，
`test/verify_examples.sh` 会安装到临时前缀并验证该集成）。

### 3.5 集成步骤

1. 按第 2 章构建库（或按 3.1 安装到系统路径）；
2. 应用代码包含所需头文件（如 `ssn_client.h`、`ssn_server.h`、`ssn_version.h`），链接
   `-lssn_transport -lpthread`；CMake 项目可用 `find_package(ssn)`（见 3.4）；
3. 第一个应用（server + client + 版本打印）完整示例见 `docs/06-使用手册/使用指南.md`
   「2.3 第一个应用」；
4. 可参考 `examples/basic/01_hello_world/Makefile` 的编译与链接参数（含 rpath 设置）。

## 4. 常见问题

### 4.1 运行时找不到 libssn_transport.so

- **现象**：`error while loading shared libraries: libssn_transport.so: cannot open shared
  object file`。
- **原因**：动态库搜索路径未包含库所在目录。
- **解决**：示例与仓库内程序已内置 rpath 可直接运行；若将库安装/拷贝到自定义目录，请设置
  `export LD_LIBRARY_PATH=<库所在目录>:$LD_LIBRARY_PATH`，或编译时添加
  `-Wl,-rpath,<库所在目录>`。

### 4.2 WSL 构建路径

- 仓库位于 Windows（如 `D:\personal\cd-ipc-ssn`），Linux 构建环境在 WSL：挂载路径为
  `/mnt/d/personal/cd-ipc-ssn`。
- 一键验证：`wsl bash -c "cd /mnt/d/personal/cd-ipc-ssn && bash test/run_tests.sh"`。
- 注意：`/mnt/d` 为 Windows 挂载点，I/O 较慢，建议 `make -j` 控制并行度；若性能敏感，可将
  仓库拷贝到 WSL 本地文件系统后构建。

### 4.3 UDP server 握手限制

- **现象**：基于 UDP 的 `ssn_server` 无法建立握手连接，连接/断开回调不会触发。
- **原因**：UDP 为无连接传输，`udp_transport_accept` 恒返回 NULL（不支持 accept/server 模式
  握手），`ssn_server` 无法运行于 UDP 之上，仅适用于 client 模式点对点收发；示例 `03_udp` 的
  server 端仅为演示 bind/recv 流程。
- **说明**：详见 `docs/03-设计/架构设计/传输层设计.md`「UDP 传输」章节的限制标注。

### 4.4 高级测试需要手工服务端

- `test_comprehensive`、`test_thread_safety`、`test_stress` 三个高级测试需要先手工启动服务端
  再运行（`run_tests.sh` 不包含它们），适用于本地/CI 的并发与性能验证。
