## 1. 引言

### 1.1 项目背景

SSN（Scalable Socket Network，可扩展套接字网络）是一个基于统一命名前缀 `ssn_` 的轻量级 IPC/分布式通信框架，支持 RPC、发布/订阅和消息传输功能。随着边缘计算和物联网技术的发展，系统已从单机进程间通信扩展为跨设备、跨网络的分布式通信框架，当前版本 v2.4.3。

### 1.2 设计目标

1. **多协议支持**：实现对 Unix Socket、TCP 和 UDP 三种传输协议的统一支持
2. **节点抽象模型**：采用类似 DDS 的分布式节点架构，淡化传统客户端/服务端模式
3. **节点发现机制**：提供节点自动发现与注册功能
4. **QoS 支持**：提供服务质量保障的基础框架

上述目标在 v2.0.0 起逐步落地（详见 1.4 版本历程），其中 TLS/DTLS 安全传输、连接池、压缩等能力仍为愿景方向（见第 10 章）。

### 1.3 设计原则

1. **向后兼容**：确保现有 API 和功能不受影响
2. **模块化设计**：各组件职责清晰，便于扩展和维护
3. **性能优先**：在保证功能完整性的前提下优化性能
4. **安全性**：安全通信为长期演进方向，当前以传输隔离与访问控制为主

### 2.2 分层说明

| 层次 | 职责 |
|------|------|
| 应用层 | 用户业务代码入口，直接调用节点层或客户端/服务端 API |
| 节点抽象层 | `ssn_node_t` 统一封装服务端与客户端双角色能力，对外提供发布/订阅、RPC、消息收发接口 |
| 客户端/服务端层 | `ssn_client_t` 与 `ssn_server_t`，提供面向连接的传统通信模型 |
| 协议层 | 模块化协议实现：`ssn_rpc`（请求/响应）、`ssn_pubsub`（发布/订阅）、`ssn_msg`（消息收发），由 `ssn_frame` 统一完成线协议编解码 |
| 传输层 | 统一传输接口 + 工厂（`ssn_transport_factory`），支持 Unix Socket、TCP、UDP 三种实现 |
| VSI 层 | 内部平台抽象（套接字、事件、线程），保留 `ipc_` 前缀，不对外暴露 |

### 2.3 核心模块

| 组件 | 类型 | 文件 |
|------|------|------|
| `ssn_node_t` | 节点抽象（服务端+客户端双角色） | `src/node/ssn_node.c` |
| `ssn_client_t` | 客户端 | `src/ssn_client.c` |
| `ssn_server_t` | 服务端 | `src/ssn_server.c` |
| `ssn_transport_t` | 传输层统一接口 | `src/transports/` |
| `ssn_rpc_req_t` / `ssn_rpc_rep_t` | RPC 协议模块 | `src/protocol/rpc/` |
| `ssn_pubsub_pub_t` / `ssn_pubsub_sub_t` | 发布/订阅协议模块 | `src/protocol/pubsub/` |
| `ssn_msg_send_t` / `ssn_msg_recv_t` | 消息协议模块 | `src/protocol/msg/` |

### 2.4 命名约定

- 所有公开符号使用 `ssn_` 前缀
- VSI 平台抽象层（内部）保留 `ipc_` 前缀
- 类型名：`ssn_<module>_t`（如 `ssn_client_t`、`ssn_transport_t`）
- 函数名：`ssn_<module>_<action>`（如 `ssn_node_create`、`ssn_client_connect`）
- 宏：`SSN_<UPPER_CASE>`（如 `SSN_MAX_PACKET_SIZE`、`SSN_MSG_TYPE_PUBLISH`）

### 2.5 C++ 服务框架（v2.4.0）

**定位**：面向应用开发者的服务开发框架（`libssn_framework.so`，C++17）——在 C API
之上封装「服务开发」的常见工作量：类型安全的方法注册与调用、内置管理端点、PubSub
发布/订阅与一行式生命周期编排，让开发者以最少的样板代码交付 IPC 服务。

**分层位置**：构建于节点抽象层之上（直接调用 `ssn_node_t` 能力，向下兼容全部 C
API）；应用层可直接在框架上开发，无需接触节点/客户端/服务端层的实现细节。

| 组件 | 职责（一行） |
|------|--------------|
| `ServiceBase` | 服务生命周期状态机（Created/Initialized/Started/Stopped），提供 OnInit/OnShutdown 钩子 |
| `ServiceTask` | 线程池服务基类：svc() 线程入口 + activate/wait/requestShutdown 线程管理 |
| `ServiceManager` | 服务管理器：Run\<T\>() 一行编排「初始化 → 启动 → 等待信号 → 优雅停止」 |
| `SsnService` | 服务端基类：TCP 监听、方法注册与分发（RegisterMethod/registerJson）、内置端点 /urls /health /version、publish 发布 |
| `SsnClient` | 客户端：连接管理、同步 Call\<Req,Resp\> 调用、PubSub 订阅 |

使用方式与教学示例见「C++ 服务框架指南」（`docs/06-使用手册/C++服务框架指南.md`）。

## 3. 节点抽象模型

### 3.1 节点概念定义

节点是分布式系统中的基本通信单元（已实现，v2.0.0 起），每个节点具有以下特性：

1. **唯一标识**：全局唯一的节点 ID
2. **多角色支持**：可同时作为数据生产者、消费者或服务提供者（`SSN_NODE_CAP_SERVER` / `SSN_NODE_CAP_CLIENT` / `SSN_NODE_CAP_PUBSUB`）
3. **自描述能力**：包含节点类型、能力、服务等信息
4. **动态生命周期**：支持动态加入和离开网络

### 3.2 节点数据结构

```c
typedef struct ssn_node {
    // 基础信息
    char node_id[64];              // 节点唯一标识
    char node_type[32];            // 节点类型
    char node_name[64];            // 节点名称

    // 能力描述
    uint32_t capabilities;         // 能力位掩码
    ssn_qos_config_t default_qos;  // 默认 QoS 配置

    // 网络信息
    ssn_device_address_t address;  // 节点地址
    time_t last_heartbeat;         // 最后心跳时间

    // 状态管理
    ssn_node_state_t state;        // 节点状态
    uint32_t ref_count;            // 引用计数

    // 通信资源
    ssn_transport_t* transport;    // 传输层实例
    ssn_security_context_t* security; // 安全上下文（预留，愿景未实现）

    // 服务注册
    ssn_service_info_t services[MAX_SERVICES]; // 注册的服务
    int service_count;

    // 订阅管理
    ssn_subscription_t subscriptions[MAX_SUBSCRIPTIONS]; // 订阅的主题
    int subscription_count;
} ssn_node_t;
```

### 3.3 节点状态机

```
         ┌─────────────┐
         │   INITIAL   │
         └──────┬──────┘
                │ ssn_node_create()
                ▼
         ┌─────────────┐
         │   CREATED   │
         └──────┬──────┘
                │ ssn_node_start()
                ▼
         ┌─────────────┐
         │   ACTIVE    │◄──┐
         └──────┬──────┘   │
                │          │ 网络故障/恢复
         ssn_node_stop()   │
                ▼          │
         ┌─────────────┐   │
         │   STOPPED   │───┘
         └──────┬──────┘
                │ ssn_node_destroy()
                ▼
         ┌─────────────┐
         │  DESTROYED  │
         └─────────────┘
```

### 3.4 节点通信模式

1. **对等通信**：节点间直接通信，无中心服务器
2. **发布/订阅**：基于主题的数据分发（`ssn_node_publish` / `ssn_node_subscribe`）
3. **请求/响应**：类似 RPC 的同步通信（`ssn_node_rpc_call` / `ssn_node_add_rpc_method`）
4. **消息传递**：点到点消息收发（`ssn_node_send_to_peer`）

## 4. 协议层设计

### 4.1 协议模块化

协议层自 v2.1.0 起重构为独立模块，由 `ssn_frame` 统一提供线协议编解码：

| 模块 | 类型 | 职责 |
|------|------|------|
| `ssn_rpc` | 请求/响应 | 服务端方法注册、客户端同步调用与回调 |
| `ssn_pubsub` | 发布/订阅 | 主题订阅、消息发布与分发 |
| `ssn_msg` | 消息 | 点到点消息发送与接收 |

### 4.2 统一传输接口

传输类型枚举与 `src/transports/ssn_transport.h` 实际定义一致：

```c
// 传输类型定义（与源码 ssn_transport.h 一致）
```

### 4.4 协议适配器实现

传输层包含三种实现与统一工厂：

```c
// TCP 传输实现
typedef struct tcp_transport_impl {
    int sock_fd;                    // 套接字描述符
    struct sockaddr_in addr;        // 地址信息
    bool is_server;                 // 是否为服务器
    bool non_blocking;              // 是否非阻塞
    ssn_connection_stats_t stats;   // 连接统计
} tcp_transport_impl_t;

// UDP 传输实现
typedef struct udp_transport_impl {
    int sock_fd;                    // 套接字描述符
    struct sockaddr_in addr;        // 本地地址
    struct sockaddr_in peer_addr;   // 对端地址
    bool multicast;                 // 是否组播
    ssn_packet_buffer_t recv_buf;   // 接收缓冲区
} udp_transport_impl_t;
```

实现文件：`src/transports/ssn_transport_unix.c`、`ssn_transport_tcp.c`、`ssn_transport_udp.c`、`ssn_transport_factory.c`。

### 5.2 发现消息格式

```c
// 发现消息类型
typedef enum {
    SSN_DISCOVERY_ANNOUNCE,      // 节点宣告
    SSN_DISCOVERY_QUERY,         // 节点查询
    SSN_DISCOVERY_RESPONSE,      // 查询响应
    SSN_DISCOVERY_HEARTBEAT,     // 心跳消息
    SSN_DISCOVERY_GOODBYE        // 节点离开
} ssn_discovery_msg_type_t;

// 发现消息结构
typedef struct __attribute__((packed)) {
    uint8_t magic;               // 魔数 (0xCD)
    uint8_t version;             // 协议版本
    uint8_t msg_type;            // 消息类型
    uint8_t ttl;                 // 生存时间
    uint32_t node_id_hash;       // 节点 ID 哈希
    uint16_t service_port;       // 服务端口
    uint16_t reserved;
    char node_id[64];            // 节点 ID
    char node_type[32];          // 节点类型
    char services[128];          // 服务列表 (JSON格式)
} ssn_discovery_packet_t;
```

### 5.3 发现算法流程

1. **启动阶段**：
   - 节点启动时发送宣告消息
   - 监听发现端口
   - 建立本地节点表

2. **发现阶段**：
   - 定期发送心跳消息
   - 响应查询请求
   - 更新节点状态

3. **维护阶段**：
   - 检测离线节点
   - 处理网络分区
   - 同步节点信息

4. **离开阶段**：
   - 发送离开通知
   - 清理相关资源

### 5.4 容错机制

1. **心跳检测**：定期发送心跳，超时判定为离线
2. **重试机制**：失败操作自动重试
3. **状态同步**：节点状态变化时同步到其他节点
4. **网络分区处理**：检测并处理网络分区情况

## 6. QoS 支持框架（基础能力）

### 6.1 QoS 架构层次

QoS 基础框架已实现（v2.0.0 起）：可靠性、优先级、带宽控制的核心配置模型与接口。多级调度队列、流量整形、延迟保障等细化算法属于愿景深化方向。

```
┌─────────────────────────────────────────────────────────────┐
│                    QoS 策略层 (QoS Policy Layer)            │
```

### 6.3 可靠性等级实现

1. **尽力而为传输**：
   - 直接发送，无确认机制
   - 适用于实时音视频等容忍丢包的场景

2. **至少一次传输**：
   - 发送 + 确认 + 超时重传
   - 适用于数据采集等允许重复的场景

3. **至多一次传输**：
   - 发送 + 消息去重
   - 适用于状态同步等不允许重复的场景

4. **精确一次传输**：
   - 两阶段提交 + 幂等处理
   - 适用于事务性操作等关键场景

5. **可靠传输**：
   - 序列号 + 确认 + 重传 + 顺序保证
   - 适用于文件传输等需要保证完整性的场景

## 11. DDS 对标与演进路线

### 11.1 为什么对标 DDS

DDS（Data Distribution Service，OMG 标准）是数据分发领域的行业标准，其核心模型 DCPS（Data-Centric Publish-Subscribe，以数据为中心的发布/订阅）与 SSN 的发布/订阅能力存在概念同源性。对标 DDS 的根本目的是**学习 DDS**：以 DDS 的概念模型为参照，逐步设计、渐进靠近，将 SSN 从「以连接为中心的 IPC 框架」演进为「以数据为中心的分布式通信框架」。

### 11.2 目标形态（DCPS 模型映射总览）

| DDS 概念 | SSN 演进目标 |
|----------|-------------|
| DomainParticipant（域参与者） | `ssn_domain_t`（通信域入口） |
| Topic（类型化主题） | `ssn_topic_t`（名称 + 类型名占位） |
| Publisher / DataWriter | `ssn_publisher_t`（数据写入） |
| Subscriber / DataReader | `ssn_subscriber_t`（回调式读取） |
| QoS 策略（RELIABILITY 等） | `ssn_qos_t`（轻量策略子集） |
| 发现机制（SPDP/SEDP） | 增强现有组播/目录发现 |

### 11.3 三阶段演进路线总览

| 阶段 | 目标版本 | 主题 | 一句话概述 |
|------|---------|------|-----------|
| 阶段 1 | 2.4.0 | DCPS 概念模型 | 引入 Domain/Topic/Publisher/Subscriber 抽象层，建立「数据为中心」心智模型 |
| 阶段 2 | 2.5.0 | QoS 策略语义 | 引进 RELIABILITY/HISTORY/DEADLINE/LIFESPAN/PARTITION 五种核心策略语义 |
| 阶段 3 | 2.6.0 | 发现与高级特性 | 增强为 SPDP/SEDP 风格发现，引入 ContentFilteredTopic 与 Listener/WaitSet |

### 11.4 定位声明

SSN 采用**概念借鉴型**定位：借鉴 DDS 的概念模型与关键机制，保持轻量 IPC 定位。**不追求** OMG 规范全量实现、RTPS 线协议互操作或与真实 DDS 实现（FastDDS/OpenDDS 等）兼容。详细设计见 `docs/03-设计/DDS演进设计.md`。

## 13. 总结

SSN 分布式通信框架已完成从单机进程间通信到跨设备分布式通信的演进。当前版本（v2.4.3）具备以下已实现能力：

1. **架构先进性**：采用类似 DDS 的分布式节点模型（`ssn_node_t` 双角色）
2. **功能完整性**：支持多协议传输、节点发现、QoS 基础与模块化协议层
3. **兼容性保障**：统一 `ssn_` 命名，提供迁移指南确保平滑升级
4. **可测试性**：7 个自动化测试套件共 122 例，覆盖传输、协议、节点与 API 全链路

对于 TLS/DTLS 安全传输、连接池与压缩等愿景方向，建议按演进节奏在后续版本评估投入，详见第 10 章能力矩阵。
