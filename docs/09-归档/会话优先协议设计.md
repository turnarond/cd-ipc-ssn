# SSN 会话优先协议前缀设计方案

## 背景与目标

### 当前架构分析

当前代码结构：
```
ssn_client.c / ssn_server.c
    ↓
ssn_transport.c (unix/tcp/udp)
```

**存在的问题**：
1. 用户需要手动指定传输层协议（tcp、udp、unix）
2. 会话层和传输层的关系不够直观
3. 没有默认的传输层协议选择
4. RPC 和 MSG 无法区分发送端和接收端

### 目标

设计一套**会话优先**的协议前缀方案：
- **用户只需指定会话层协议**：请求/应答、发送/接收、发布/订阅
- **系统自动选择默认传输层**：会话层对应默认传输协议
- **支持显式指定传输层**：允许用户覆盖默认选择
- **角色清晰**：通过协议前缀明确区分发送端和接收端

## 会话优先协议前缀设计

### 核心设计理念

```
[<transport>]<session>://<address>
```

**格式说明**：
- `<transport>`: 可选，传输层协议前缀 (udp, ipc)，不指定时使用默认传输
- `<session>`: 会话层协议 (req, rep, send, recv, pub, sub)
- `<address>`: 网络地址或套接字路径

### 会话层协议（0MQ风格）

| 协议 | 角色 | 说明 | 示例 |
|------|------|------|------|
| `req://` | 请求端 | 发送请求，接收响应 | `req://127.0.0.1:8080` |
| `rep://` | 应答端 | 接收请求，发送响应 | `rep://127.0.0.1:8080` |
| `send://` | 发送端 | 主动发送消息 | `send://127.0.0.1:7070` |
| `recv://` | 接收端 | 被动接收消息 | `recv://127.0.0.1:7070` |
| `pub://` | 发布端 | 发布消息到主题 | `pub://127.0.0.1:9090` |
| `sub://` | 订阅端 | 订阅主题消息 | `sub://127.0.0.1:9090` |

### 通信模式对照表

| 通信模式 | 发送端 | 接收端 | 协议前缀 |
|----------|--------|--------|----------|
| **请求-响应** | 请求端 | 应答端 | `req://` / `rep://` |
| **单向消息** | 发送端 | 接收端 | `send://` / `recv://` |
| **发布-订阅** | 发布端 | 订阅端 | `pub://` / `sub://` |

### 传输层覆盖

| 传输前缀 | 会话协议 | 实际传输 | 示例 |
|---------|----------|----------|------|
| `udp` | `req` | UDP | `udpreq://127.0.0.1:8080` |
| `udp` | `rep` | UDP | `udprep://127.0.0.1:8080` |
| `udp` | `send` | UDP | `udpsend://127.0.0.1:7070` |
| `udp` | `recv` | UDP | `udprecv://127.0.0.1:7070` |
| `udp` | `pub` | UDP | `udppub://127.0.0.1:9090` |
| `udp` | `sub` | UDP | `udpsub://127.0.0.1:9090` |
| `ipc` | `req` | Unix Socket | `ipcreq:///tmp/node.sock` |
| `ipc` | `rep` | Unix Socket | `ipcrep:///tmp/node.sock` |
| `ipc` | `send` | Unix Socket | `ipcsend:///tmp/node.sock` |
| `ipc` | `recv` | Unix Socket | `ipcrecv:///tmp/node.sock` |
| `ipc` | `pub` | Unix Socket | `ipcpub:///tmp/node.sock` |
| `ipc` | `sub` | Unix Socket | `ipcsub:///tmp/node.sock` |

## 实现方案

### 1. 协议解析结构

```c
/**
 * @brief 会话优先协议解析结果
 */
typedef struct {
    // 传输层
    ssn_transport_type_t transport;    // TCP/UDP/Unix Socket

    // 会话层
    ssn_session_type_t session;       // 请求/应答/发送/接收/发布/订阅

    // 地址信息
    char host[256];                    // 主机地址
    int port;                         // 端口号
    char path[256];                    // Unix Socket路径

    // 服务信息
    char service_path[128];            // 服务路径
    char method_name[64];              // 方法名 (用于RPC请求)
    char topic_name[64];               // 主题名 (用于发布订阅)
} ssn_session_url_t;
```

### 2. 会话类型枚举

```c
/**
 * @brief IPC会话类型（0MQ风格）
 */
typedef enum {
    IPC_SESSION_REQ = 0,       // 请求端（发送请求，接收响应）
    IPC_SESSION_REP,            // 应答端（接收请求，发送响应）
    IPC_SESSION_SEND,           // 发送端（主动发送消息）
    IPC_SESSION_RECV,           // 接收端（被动接收消息）
    IPC_SESSION_PUB,            // 发布端
    IPC_SESSION_SUB             // 订阅端
} ssn_session_type_t;
```

### 3. URL解析API

```c
/**
 * @brief 解析会话优先协议URL
 *
 * 解析格式: [<transport>]<session>://<address>
 * 例如: req://127.0.0.1:8080, udpsend://127.0.0.1:7070
 *
 * @param url 会话优先协议URL
 * @param result 解析结果
 * @return true 成功, false 失败
 */
SSN_API bool ssn_session_url_parse(const char *url, ssn_session_url_t *result);

/**
 * @brief 根据URL创建客户端（请求端/发送端/订阅端）
 *
 * @param url 会话优先协议URL
 * @param callback 回调函数
 * @param arg 回调参数
 * @return 客户端实例, NULL失败
 */
SSN_API ssn_client_t *ssn_client_create_from_session_url(
    const char *url,
    ssn_client_msg_handler_t callback,
    void *arg);

/**
 * @brief 根据URL创建服务器（应答端/接收端/发布端）
 *
 * @param url 会话优先协议URL
 * @return 服务器实例, NULL失败
 */
SSN_API ssn_server_t *ssn_server_create_from_session_url(const char *url);

/**
 * @brief 连接到会话优先协议地址
 *
 * @param client 客户端实例
 * @param url 会话优先协议URL
 * @param timeout 超时时间
 * @return true成功, false失败
 */
SSN_API bool ssn_client_connect_session_url(
    ssn_client_t *client,
    const char *url,
    const struct timespec *timeout);
```

## 使用示例

### 示例1：请求-应答模式（默认TCP）

```c
// 应答端 - 提供RPC服务（服务器）
ssn_server_t *server = ssn_server_create_from_session_url("rep://0.0.0.0:8080");
ssn_server_start_url(server);

// 注册RPC方法
ssn_server_add_method(server, &(ssn_url_ref_t){"/add", 4},
    handle_rpc, NULL);

// 请求端 - 发起RPC调用（客户端）
ssn_client_t *client = ssn_client_create_from_session_url(
    "req://127.0.0.1:8080", NULL, NULL);
ssn_client_connect_session_url(client, "req://127.0.0.1:8080",
    &(struct timespec){5, 0});

// 调用RPC
ssn_client_call(client, &(ssn_url_ref_t){"/add", 4},
    &data, callback, NULL, 1000);
```

### 示例2：单向消息模式（默认TCP）

```c
// 接收端 - 被动接收消息（服务器）
ssn_server_t *receiver = ssn_server_create_from_session_url("recv://0.0.0.0:7070");
ssn_server_start_url(receiver);

// 设置消息回调
ssn_server_set_message_handler(receiver, on_message, NULL);

// 发送端 - 主动发送消息（客户端）
ssn_client_t *sender = ssn_client_create_from_session_url(
    "send://127.0.0.1:7070", NULL, NULL);
ssn_client_connect_session_url(sender, "send://127.0.0.1:7070",
    &(struct timespec){5, 0});

// 发送消息
ssn_client_message(sender, &(ssn_url_ref_t){"/queue", 6},
    &(ssn_data_ref_t){"Hello", 5});
```

### 示例3：发布-订阅模式（UDP传输）

```c
// 发布端 - UDP发布消息（服务器）
ssn_server_t *publisher = ssn_server_create_from_session_url("udppub://0.0.0.0:9090");
ssn_server_start_url(publisher);

// 发布消息
ssn_server_publish(publisher, &(ssn_url_ref_t){"/news", 5},
    &(ssn_data_ref_t){"Breaking news!", 14});

// 订阅端 - UDP订阅消息（客户端）
ssn_client_t *subscriber = ssn_client_create_from_session_url(
    "udpsub://127.0.0.1:9090", on_message, NULL);
ssn_client_connect_session_url(subscriber, "udpsub://127.0.0.1:9090",
    &(struct timespec){5, 0});

// 订阅主题
ssn_client_subscribe(subscriber, &(ssn_url_ref_t){"/news", 5},
    NULL, NULL, 1000);
```

### 示例4：Unix Socket请求-应答模式


## 向后兼容性

### 保持旧API兼容

```c
// 旧API仍然支持
ssn_server_create("tcp://0.0.0.0:8080");  // 继续有效
ssn_client_connect(client, "unix:///tmp/test.sock", &timeout);

// 新API提供更简洁的语法
ssn_server_create_from_session_url("rep://0.0.0.0:8080");
ssn_client_create_from_session_url("req://127.0.0.1:8080", NULL, NULL);
ssn_server_create_from_session_url("recv://0.0.0.0:7070");
ssn_client_create_from_session_url("send://127.0.0.1:7070", NULL, NULL);
```

### 地址自动检测

- **会话优先格式**：`req://`, `rep://`, `send://`, `recv://`, `udpreq://`, `ipcreq://` 等
- **传统格式**：`tcp://`, `udp://`, `unix://` 等（保持兼容）
- **无前缀**：默认为 Unix Socket（向后兼容）

## 注意事项

1. **大小写敏感**：协议名必须小写（req, rep, send, recv, pub, sub, udp, ipc等）
2. **端口范围**：TCP/UDP端口范围 1-65535
3. **路径长度**：Unix Socket路径最大长度受系统限制
4. **默认传输**：未指定传输层时使用TCP
5. **优先级**：显式传输前缀优先于默认传输
6. **角色配对**：req配对rep，send配对recv，pub配对sub

## 总结

通过会话优先的协议前缀方案（0MQ风格），用户可以：

1. **简化使用**：只需指定会话层协议，系统自动选择传输层
2. **角色清晰**：通过 req/rep、send/recv、pub/sub 明确区分通信角色
3. **灵活配置**：可以显式指定传输层协议（udp、ipc）
4. **直观明了**：URL格式直接反映会话类型和通信模式
5. **向后兼容**：保持对传统格式的支持

这套设计让用户更加关注业务逻辑（会话层），而不是底层传输细节，符合现代通信库的设计趋势。
