# C++ 服务框架关键决策归档

## 文档状态

本文件提炼 2026 年 8 月 C++ 服务框架设计与开发者体验规划中的长期决策。原执行计划已完成或过时，不再作为实施入口；当前行为以正式设计、使用手册和代码为准。

## 架构边界

- 框架采用 `ServiceBase → ServiceTask → SsnService` 渐进分层，由 `ServiceManager` 编排生命周期。
- 公开接口位于 `include/ssn/framework/`，实现位于 `src/framework/`；框架层仅依赖 SSN 公开 C API，不跨越到 `src/vsi/` 等内部实现。
- `SsnService` 当前使用 TCP；`SsnClient` 同步调用为单 in-flight，不能宣称同一客户端支持并发请求。
- C++17 框架构建为独立动态库 `ssn_framework`，避免改变 C API 与既有 ABI。

## 依赖与许可

- JSON DTO 使用 `nlohmann/json` 单头依赖，版本、来源、许可及校验信息必须记录在 `third_party/nlohmann/README.md`。
- 外部项目只允许借鉴公开 API 形态，代码应独立实现；引入第三方代码前必须确认许可证和来源。

### 来源审计结论

原始构想曾考虑移植外部服务框架骨架，并将许可证确认列为前置条件；最终实施计划改为仅参考公开 API 形态、全部代码独立重写。仓库内证据如下：

- 框架骨架始于提交 `27dc215f`，生命周期实现始于 `059d7182`，后续组件按独立 TDD 提交逐步落地。
- `include/ssn/framework/` 与 `src/framework/` 未发现原构想所述外部项目名称、版权声明或源文件标识，文件头均声明为 SSN Project。
- 唯一纳入仓库的第三方实现为 `third_party/nlohmann/json.hpp`；其 README 已记录 v3.11.3、MIT License、来源及 SHA256。

据当前仓库证据，框架采用独立实现，不存在已知的外部骨架代码移植。该结论是仓库来源审计记录，不替代专业法律意见；未来若发现外部代码来源证据，应立即停止发布并登记 Issue 复核许可证。
