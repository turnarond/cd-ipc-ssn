## 1. 背景与目标

### 1.1 现状问题（2026-08-02 全量分析结论）

docs/ 下共 16 篇文档（约 10,000 行），存在四类问题：

1. **大量过时**：`架构设计总览.md`、`外层架构重构方案.md`、`2.0版本实施规划.md` 标注「待实施/草案」的模块（client/server/node）在 2.1~2.3.0 已全部完成；`会话优先协议设计.md` 是未采纳方案却无任何标注
2. **命名残留**：`QoS框架设计.md`（127 处）、`节点发现设计.md`（117 处）、`节点抽象设计.md`（114 处）、`架构设计总览.md`（32 处）仍用旧 `ipc_` 前缀
3. **重叠矛盾**：`传输层设计.md` 与 `协议适配器设计.md` 逐字段重复；`使用指南.md`（1.0 时代）与 `API使用指南.md` 同一 API 两套冲突签名；错误码三套并存（`SSN_ERR_*`/`SSN_ECODE_*`/数字）
4. **类别缺失**：02 需求分析、05 部署手册完全缺失；01 白皮书弱覆盖

### 1.2 目标

- 按阅读顺序编号重组 docs 目录（01-白皮书 → 07-测试方案，09-归档）
- 合并重叠文档、修正过时状态与命名残留、归档历史方案
- 精修高价值文档（API 使用指南、协议层模块化设计、测试方案、传输层设计）
- 改造文档总索引，修复全部死链
- **策略：整理归档为主**（不全面重写、不删除历史）

## 4. 改写规则

1. **命名统一**：正文中 `ipc_` 前缀 → `ssn_`。两类豁免：① 迁移指南的映射表；② 归档文档正文
2. **文档信息表**：每篇有效文档头部统一加信息表（文档版本、状态：`有效/已实施/部分过时/已归档`、更新日期），格式参照 `架构设计总览.md` 现有信息表
3. **归档标注**：归档文档头部加标注块（原因 + 日期），正文不改
4. **未落地特性标注**：TLS/连接池/健康检查（传输层）、目录服务模式（节点发现）、全局 API 表设计（节点抽象）、QoS 动态调整等，统一标注「未实现/未落地」而非删除，保留设计参考价值
