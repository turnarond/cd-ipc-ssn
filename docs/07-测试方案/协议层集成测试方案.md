## 概述

本文档描述了SSN协议层的完整集成测试方案，涵盖RPC、发布订阅、消息三种协议模块的功能验证。

## 测试架构

### 测试层次

1. **单元测试** (`test_protocol.c`)
   - 协议模块的创建与销毁
   - 协议类型和角色验证
   - 方法注册与注销
   - 无传输层时的错误处理
   - 资源创建/销毁循环测试

2. **集成测试** (`test_protocol_integration.c`)
   - RPC请求-响应流程
   - 消息发送-接收流程
   - 发布订阅流程
   - 多协议并发测试
   - 异常和边界条件测试

## 测试用例详细说明

### 1. 单元测试用例

#### 1.1 协议创建销毁测试
```
测试目的：验证所有协议上下文能够正确创建和销毁
测试步骤：
  1. 创建RPC请求端上下文
  2. 创建RPC应答端上下文
  3. 创建发布者上下文
  4. 创建订阅者上下文
  5. 创建消息发送端上下文
  6. 创建消息接收端上下文
  7. 按逆序销毁所有上下文
预期结果：所有创建和销毁操作成功，无内存泄漏
```

#### 1.2 协议类型和角色验证
```
测试目的：验证协议上下文正确识别类型和角色
测试用例：
  - RPC请求端：类型=SSN_PROTOCOL_RPC, 角色=SSN_ROLE_REQ
  - RPC应答端：类型=SSN_PROTOCOL_RPC, 角色=SSN_ROLE_REP
  - 发布者：类型=SSN_PROTOCOL_PUBSUB, 角色=SSN_ROLE_PUB
  - 订阅者：类型=SSN_PROTOCOL_PUBSUB, 角色=SSN_ROLE_SUB
  - 消息发送端：类型=SSN_PROTOCOL_MSG, 角色=SSN_ROLE_SEND
  - 消息接收端：类型=SSN_PROTOCOL_MSG, 角色=SSN_ROLE_RECV
预期结果：所有类型和角色识别正确
```

#### 1.3 RPC方法注册测试
```
测试目的：验证RPC方法注册和注销功能
测试步骤：
  1. 创建RPC应答端上下文
  2. 注册方法"test_method"
  3. 验证注册成功
  4. 注销方法"test_method"
  5. 验证注销成功
预期结果：注册和注销操作均成功
```

#### 1.4 无传输层错误处理测试
```
测试目的：验证协议在未连接传输层时的错误处理
测试用例：
  - RPC调用无传输层
  - 订阅操作无传输层
  - 消息发送无传输层
预期结果：所有操作返回错误码-1，日志记录错误原因
```

#### 1.5 资源创建/销毁循环测试
```
测试目的：检测内存泄漏和资源管理问题
测试步骤：
  1. 循环20次创建和销毁所有协议上下文
  2. 记录每次创建和销毁的结果
预期结果：所有20次循环均成功完成，无内存泄漏
```

### 2. 集成测试用例

#### 2.1 RPC Echo测试
```
测试ID: INT_RPC_001
测试目的：验证RPC基础请求-响应功能
测试场景：
  1. 启动RPC服务器线程（端口9981）
  2. 客户端连接到服务器
  3. 客户端发送"Hello RPC!"到echo方法
  4. 服务器收到请求并原样返回
  5. 客户端验证响应数据
预期结果：
  - RPC调用发送成功（返回码=0）
  - 在3秒内收到响应
  - 响应数据与发送数据一致
测试超时：5秒
```

#### 2.2 RPC Add测试
```
测试ID: INT_RPC_002
测试目的：验证RPC参数和返回值处理
测试场景：
  1. 启动RPC服务器线程（端口9981）
  2. 客户端连接到服务器
  3. 客户端发送两个整数(15, 25)到add方法
  4. 服务器计算15+25=40并返回
  5. 客户端验证结果为40
预期结果：
  - RPC调用发送成功
  - 在3秒内收到响应
  - 响应结果正确（40）
测试超时：5秒
```

#### 2.3 消息发送接收测试
```
测试ID: INT_MSG_001
测试目的：验证点对点消息传输功能
测试场景：
  1. 启动消息服务器线程（端口9982）
  2. 客户端连接到服务器
  3. 客户端发送"Hello Message!"
  4. 服务器接收并验证消息
预期结果：
  - 消息发送成功
  - 在3秒内收到消息
  - 消息内容正确
测试超时：5秒
```

#### 2.4 发布订阅测试
```
测试ID: INT_PUBSUB_001
测试目的：验证发布订阅功能
测试场景：
  1. 启动发布订阅服务器线程（端口9983）
  2. 客户端连接到服务器
  3. 客户端订阅"test_topic"
  4. 客户端发布"Hello PubSub!"到"test_topic"
  5. 客户端接收消息
预期结果：
  - 订阅操作成功
  - 发布操作成功
  - 接收到发布的消息
测试超时：5秒
```

#### 2.5 多协议并发测试
```
测试ID: INT_MULTI_001
测试目的：验证多协议并发执行
测试场景：
  1. 并发启动多个RPC客户端
  2. 每个客户端发送多个不同方法的请求
  3. 验证所有请求都能正确处理
预期结果：所有并发客户端均能正常通信
测试超时：10秒
```

## 测试执行指南

### 编译测试
```bash
# 在仓库根目录构建，构建产物统一输出到 build/ 目录（相对路径，不依赖绝对路径）
mkdir -p build && cd build
cmake ..
make
```

### 运行单元测试
```bash
# 构建后在 build/ 目录下执行各测试可执行文件
./test_protocol
```

### 运行集成测试
```bash
./test_protocol_integration
```

### 运行所有测试
```bash
ctest
# 或一键运行全部测试：bash test/run_tests.sh
```
