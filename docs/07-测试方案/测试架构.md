## 2. 测试框架

- 无外部测试框架：C 套件各测试文件内自定义 `ASSERT` 宏（统计 `g_tests_passed`/`g_tests_failed`），main 末尾打印 `Test results: N/N passed` 并返回退出码；C++ 套件（`test_cpp_*.cpp`）使用同构的 `CHECK` 宏（统计 `g_cpp_passed`/`g_cpp_failed`），打印 `C++ test results: N/N passed`
- 无法按用例名过滤，只能整体运行一个测试文件
- 用例组织：`test_<模块>.c` 内 `static void test_xxx(void)` 函数 + main 中的调用数组/列表；`test_cpp_*.cpp` 内 `void test_xxx()` 函数 + main 中依次调用

## 4. 部署与运行

### 4.1 构建

```bash
mkdir -p build && cd build
cmake .. && make -j$(nproc)
```

产物：`libssn_transport.so` + 各测试可执行文件（位于 `build/`）。

### 4.2 自动化运行

```bash
# 一键：构建 + 13 个自动化套件（7 个 C 套件 + 6 个 C++ 框架套件，位置无关）
bash test/run_tests.sh

# 单个套件（构建后）
cd build && ./test_transport
cd build && ./test_cpp_service_base
```

### 4.3 示例构建验证

```bash
# 构建全部 17 个示例（15 C + 2 C++，需先构建库 libssn_transport.so / libssn_framework.so）
bash test/verify_examples.sh
```

### 4.4 手工/高级测试

```bash
# 需先手工启动服务端（三个高级套件）
./test_comprehensive
./test_thread_safety
./test_stress
```

### 4.5 平台说明

- 仓库位于 Windows，Linux 构建/测试环境在 WSL：`wsl bash -c "cd /mnt/d/personal/cd-ipc-ssn && bash test/run_tests.sh"`
- 测试脚本保持 LF 行尾（.gitattributes 强制）；`.sh` 脚本位置无关（基于自身路径定位仓库根）
